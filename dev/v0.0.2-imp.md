状態：実装準備済み・未着手。2026-09-09の補足で旧案を改訂。[要求](v0.0.2-req.md)が判断基準、[進捗](v0.0.2-task.md)で実装を管理する。基準はv0.0.1 / 2ac26d9。実行版・既存プロジェクトは変更していない。

## 1. マージの基本方針

入力ファイルの名前・パス・所属ではなく元テキストを照合する。行とテイクには固定IDを持たせるが、元ファイルの固定ID・ファイル版は導入しない。ファイル選択中の名前表示は一時的な入力確認に限定し、対応判断や永続保存に必要としない。

複数Markdownは確認した入力順で結合して一つの新原稿とする。「新規追加」「全体の更新」「範囲の更新・統合」で対象を選び、追加・部分更新では対象外の既存行を残す。全体更新は新原稿の順序をそのまま採用し、部分更新は指定範囲内を新原稿順に差し替える。対象外を残す位置も確定前にプレビューする。ファイル単位の新版管理はしない。

マージ中は下書きだけを編集し、「台本を確定」でまとめて反映する。無効と廃棄済みは別状態とし、無効行も通常の照合対象に含める。アーカイブを自動的に現役へ戻したり、新行へ音声を移したりしない。

## 2. 維持と廃棄・新規の区別

| 判断 | 行・録音の扱い |
| --- | --- |
| 完全一致・装飾のみ変更・順序移動 | 行ID、テイク、採用、読み上げ編集、有効状態を維持 |
| 軽微変更で「既存行を維持」 | 上記を維持し、元テキストの版と差分履歴を更新。採用を自動解除しない |
| 明らかな変更で「旧行を廃棄して新規作成」 | 旧行・旧文・編集・テイク・採用記録をアーカイブ。新IDの行を新原稿位置に作成。テイク0件・採用なし・読み確認や比較結果なし |
| 新規追加 | 新ID、テイク0件。Markdownの通常の読み上げ対象判定を適用 |
| 消えた旧行の廃棄を確定 | 現役台本から外し、旧文と音声をアーカイブ |

文字差分の小ささは維持候補の根拠にすぎない。「1個→2個」などは1文字でも収録し直す可能性がある。新旧本文・旧音声を確認し、台本画面で判断を変更できる。変更行の扱いが未決定なら台本確定前に解決する。

置換新行は旧行の無効状態や読み上げ編集を継承しない。通常の初期判定とユーザーのオン／オフ指定を使う。無効状態を引き継ぐのは「既存行を維持」の場合。分割・結合は原則として旧行をアーカイブして新行を作り、録音の自動複製・切断・連結はしない。

## 3. データ構造

以下は概念名。既存Project/Segment/Takeとの対応を実装フェーズAで定義する。

| データ | 内容 |
| --- | --- |
| 原稿行・行版 | line_id、line_revision_id、元テキスト、Markdown原文、種別、階層、有効状態、現行順序。行番号は表示用 |
| 読み上げ原稿 | segment_idとline_id、編集済み本文、対応する元原稿版 |
| テイク | 既存take_id、録音時原稿、音声参照・hash。録音時の原稿を新文へ書き換えない |
| 対応履歴 | 新旧行版ペア、自動／手動、移動情報、維持／廃棄新規の判断。置換関係は追跡用であり、テイク継承ではない |
| 手動対応 | 新旧の安定した行識別子、固定フラグ、維持等の選択。再評価で変更しない |
| アーカイブ | 旧行一式、廃棄世代・理由、置換先ID（存在する場合）。通常台本・録音完了・出力から除外 |
| マージ下書き | 基準保存世代、入力内容スナップショット、新行の仮ID、対象範囲、固定対応、自動候補、確定予定順序 |
| 消去記録 | アーカイブID、削除対象参照、処理状態。保存世代からの再露出を防ぐ最小限の記録 |

旧行と新行は通常1対1で対応し、同じ旧行を複数新行に黙って使わない。固定対応は再評価・画面往復・下書き再読込でも保持する。入力を修正して対応先が消えた場合は固定を黙って解除せず「起点の再指定が必要」と表示する。

## 4. 起点を保持する照合

1. ユーザー指定の新旧ペアを最優先で固定する。1対多の競合は解決対象だが、対応線の交差は移動として許容する。
2. 残る行から元テキストの完全一致候補を全対象範囲で探索する。ファイル名による絞り込みはしない。
3. 文字類似度、前後の内容、見出し・行種別、固定起点との関係から候補を評価する。順番は補助情報であり制約にはしない。
4. 局所的な列比較（LCS等）は候補生成に使えるが、移動探索を別途行う。交差する固定起点で区間を切って対応不能にしない。
5. 重複文・短い定型文は文脈を表示してユーザーに選ばせる。正規化は検索用に限定し、原文の差分を隠さない。
6. 「固定した対応を基準に再比較」で未固定の候補だけを再計算する。ユーザーが指定した対応・解除・維持／新規の判断を初期化しない。
7. 確定予定一覧は新原稿の順序で構築する。旧順序に合わせて入力を並べ直さない。

手動起点は本人が変更・解除するまで下書きに保存し、確定時は対応履歴へ記録する。別の新規取り込みにも無条件に同じ番号の起点を適用することはせず、対象の行版を確認する。

## 5. 台本画面

- 上部：複数読込、入力順、追加／全体更新／範囲更新、対象範囲、「マージ」。
- 中央：旧文と新文、文字差分、移動、テイク数、採用、有効状態。手動で固定した対応は印を付ける。
- 詳細：旧元原稿、新元原稿、編集済み本文、録音時原稿、旧テイク試聴。
- 対応操作：新旧行を選んで「対応を固定」、変更・解除、「固定した対応を基準に再比較」。
- 行の扱い：「既存行を維持」「旧行を廃棄して新規作成」。対応なしの新規追加と旧行の廃棄／対象外として保持も指定できる。
- フィルター：変更、追加、廃棄予定、移動、要確認、無効。確定後の順序と未収録になる件数を表示。
- 最下部固定：「下書きを破棄」「台本を確定」、未解決件数。スクロールは原稿一覧内だけ。

読み上げ編集がある維持行は、旧元原稿・新元原稿・編集済み本文を比較し「編集を残す」「新原稿を使う」「手動調整」を選ぶ。既定で編集を勝手に上書きしない。ユーザーが維持として確定した採用音声は保持するが、古い文字位置の補正は別途整合確認する。

## 6. 録音画面のアーカイブ

「廃棄された行を表示」を設け、既定では非表示にする。切り替えると廃棄済み原稿・廃棄理由・旧テイクを確認でき、各音声を試聴できる。現役の前へ／後へ・連続録音・完了件数・F3/F4の対象に混ぜない。アーカイブ閲覧中は通常の収録・採用操作を無効にする。

「完全消去」は対象行とその保管テイクを明記したアプリ中央の確認後に実行する。今回は消去機能の設計だけで、既存データは消さない。

完全消去の実装は不変revisionsとの整合が必要。単なる一覧非表示では完了にしない。現役行や他テイクから参照する共有音声は削除せず、その理由を表示する。専有音声・関連生成物の削除と、過去世代からの再露出防止を消去記録と読込・履歴表示側で統一する。過去JSONに残る本文・テイク情報を除去するため、保全対象を保持した世代再構成・参照検査・アトミックな切替を設計し、途中失敗から再実行できるようにする。未削除があれば完了表示しない。

アプリ管理外へコピー済みの音声・バックアップは対象外。ストレージの物理的な復元不能化を保証する機能ではない。新規置換した行への音声自動復帰・アーカイブからの採用移植は今回の要求に含めない。

## 7. 工程連携・保存・移行

- 維持行は既存IDと採用を保ち、移動に応じて順序・階層を更新する。本文変更に依存する古い文字位置の補正・認識・比較は履歴に分け、現行結果へ誤適用しない。
- 新規置換は旧読み確認・比較結果を引き継がない。工程3・4は省略でき、現役の採用音声だけで出力できる。
- 手動出力境界・名前・間隔は保持IDへ追従する。置換・削除でIDが消える場合は影響を表示し、黙って別行へ移植しない。
- 基準保存世代が変化した場合は固定対応を保って再評価し、音声・台本の変更を古い下書きで上書きしない。対応先がなくなった起点は要確認にする。
- マージ確定は順序・アーカイブ・新規行・有効状態・採用・出力設定を一つの保存世代へ反映する。失敗時は旧状態を保持する。
- 下書きは確定台本と別保存。取消では現役台本を変えず、再読込では保存した手動対応を復元する。
- v0.0.1からの移行は既存segment_id/take_id・hash・無効状態を保持し、原稿行に固定IDを付与する。source_lineは移行の手掛かりに限定。source_markdownとTXT行を内容として移行し、元ファイル名は要求しない。
- 重複・履歴・無効行の対応が曖昧なら推測で統合しない。新保存形式を旧アプリが誤って更新しないよう形式版を更新する。原稿数・容量制限は確定前に全体で検査する。

## 8. 受入例

1. 先頭2行追加でも既存100行のテイク・採用・無効状態がずれない。
2. 軽微な句読点修正を維持と確定すると、同じID・採用・音声を保つ。
3. 1文字の数値変更でも廃棄・新規を選べ、旧行はアーカイブ、新行はテイク0件になる。
4. 大幅変更で旧編集・採点・音声が新行に付かない。旧音声はアーカイブで試聴できる。
5. 同じ内容を別名のファイル、または複数ファイルに分けて取り込んでも、結合内容が同じなら同じ候補になる。
6. 部分更新は対象外を残し、対象範囲内は新原稿順になる。
7. 重複文の新旧ペアを固定して再比較すると、固定を維持して周囲の候補が変わる。
8. A/Bの順序がB/Aになっても両方の手動対応を保持し、新順序で採用音声が並ぶ。
9. 固定対応は再比較・画面往復・下書き再読込で消えない。入力から起点を削除すると再指定を求める。
10. 無効行の軽微変更・移動は無効とテイクを保持。廃棄・新規では別IDの初期状態になる。
11. 編集済み読み上げ原稿と新元原稿の衝突を表示し、編集を無断で上書きしない。
12. アーカイブ表示を切り替えて試聴でき、通常収録・連続キー・完了・出力に混入しない。
13. 完全消去の取消は不変。実行後は再起動・履歴からも再露出せず、専有音声が消える。共有参照は壊れない。
14. 消去途中の失敗・再実行、マージ保存競合・失敗・取消で現役台本と音声を破損しない。
15. 置換した行にある手動出力境界への影響を確定前に表示する。
16. 1920×1080／1280×720で一覧だけがスクロールし、台本確定は常に見える。

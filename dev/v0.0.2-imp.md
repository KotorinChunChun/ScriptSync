状態：実装準備済み・未着手。v0.0.1の完成済み実装を基準とし、要求はv0.0.2-req.md、進捗はv0.0.2-task.mdで管理する。以下の設計を0.0.1から切り出した。

## 複数Markdownの追加・差分マージと録音対応

状態：設計のみ。アプリコード・既存プロジェクト・録音ファイルは変更していない。本節は、従来の行番号＋元テキストによる対応、および取り込み行の即時反映を置き換える案である。

### 1. 目的と基本方針

複数ファイルを一括または後から読み込み、先頭・途中・末尾への追加や既存文章の改訂を、録音との対応を確認して反映できるようにする。

- ファイル・原稿行・テイクに固定IDを持たせる。行番号、ファイル名、本文ハッシュだけを識別子にしない。
- 取り込み時の対応推定には、変更前の元テキスト、前後の順序、見出し階層、ファイルの所属を使う。録音画面で編集した読み上げ原稿を照合の基準にはしない。
- マージ候補は下書きとして扱い、画面最下部の「台本を確定」でまとめて反映する。確認中は録音・採用・出力に使用する確定台本を変更しない。
- 無効行も固定ID付きで管理する。再取り込みで一致した無効行は、変更があっても無効のまま維持する。
- 音声を自動削除しない。原稿の変更や削除と、保存済み音声の存在を分離する。

### 2. ファイルの取り込みと対象範囲

「Markdownを読み込む」は複数選択に対応し、読み込み後は取り込み一覧を表示する。一覧は追加読込・除外・並べ替えが可能。OSが返した選択順を確定順とはみなさず、画面上で順番を確認する。

各ファイルについて、取り込みの扱いを選べるようにする。

| 扱い | 対象と動作 |
| --- | --- |
| 新しい原稿として追加 | 既存原稿を残し、先頭・選択行の前後・末尾へ挿入する。既定は末尾。重複文章があれば候補を示すが、同じ文章という理由だけで既存行を消さない |
| 既存ファイルの新版として更新 | 対応する既存ファイルを指定し、そのファイル内の追加・変更・削除・移動を提案する。他ファイルは変更しない |
| 一部を取り込み・統合 | 対象ファイル／範囲を指定し、重なる行の対応と追加位置を確認する。今回含まれない既存行は既定で残す |

ファイルパス・名前・内容から更新対象を提案するが、同名別ファイルやファイル名変更を自動確定しない。複数ファイルが同じ既存ファイルを更新する場合も、同時確定せず範囲の重複を解消させる。既存の先頭に説明が追加された新版と、独立した新規ファイルの追加を区別する。

### 3. データ構造と不変条件

以下は概念名。実装時は既存のProject/Segment/Takeへ無理なく移行する。

| データ | 保存する内容 |
| --- | --- |
| 元ファイル | document_id、表示名、取り込み元パス、版ID、元Markdown、ファイル間の順序 |
| 原稿行 | line_id、document_id、元テキスト、Markdown原文、行種別、見出し所属、順序、有効／無効。元の行番号は表示・出典用のみ |
| 読み上げ原稿 | 既存segment_idとline_idの関係、現在の読み上げ用テキスト、対応する元原稿版 |
| テイク | 既存take_id、録音時の読み上げ原稿、音声ファイルとhash。将来分には録音時の行版IDも付ける |
| 対応履歴 | 旧行版→新行版、対応の理由、自動提案／ユーザー指定、追加・移動・変更・削除の判定 |
| 音声確認 | 現行行版に対する未確認／既存音声を再採用済み／再収録待ち、以前の採用take_id |
| マージ下書き | 基準の保存世代、取り込んだ版、候補対応、手動修正、確定後の順序。確定台本とは別に保持する |

同じ新行に複数の旧行を黙って対応させない。同じ旧行を複数の新行へ自動複製しない。音声ファイルの内容とテイクIDを、マージのために変更しない。

### 4. 対応候補の作り方

1. 指定された対象ファイル／範囲を優先し、対象外のファイルに勝手に対応させない。
2. 完全一致する元テキストの列を並び順に沿って探索し、対応の基準にする（LCS等の列比較）。先頭や途中の挿入があっても、それ以降の行を新規行として扱わない。
3. 一致区間の間に残った行について、文字単位の類似度、前後の一致行、見出し、種別を使い、少数文字の変更を提案する。句読点・空白・表記の正規化は候補検索用に限定し、元の差分は消さない。
4. 同一文が繰り返される場合は前後関係と出現順を使う。候補が競合する場合や短い定型文しか一致しない場合は「対応要確認」とし、類似度だけで確定しない。
5. 列から外れた一致行を移動候補として探す。章単位の移動も候補にできるが、別ファイルへの移動はユーザーに対象を確認させる。
6. 対応が見つからない新行は追加、更新対象内で消えた旧行は削除候補。追加／部分統合では、取り込みに含まれない既存行を削除候補にしない。

数値が変わった「1個／2個」なども必ず変更として表示する。発音が同じかどうかを自動判定して既存音声を再採用しない。

### 5. マージ画面

上部の「行を確認」は「マージ」に変更する。入力内容・追加ファイル・対象範囲から候補を作成し、次の画面で確認する。

- 上部：取り込みファイル一覧、追加／更新／部分統合、対象ファイル、挿入位置、マージ実行。
- 中央：変更前と変更後の行を左右で比較。文字差分、対応先、移動元／先、有効状態、テイク数、旧採用テイクを表示する。原稿一覧だけを内部スクロールする。
- 行を選択した詳細欄：変更前元原稿、変更後元原稿、録音時の原稿、録音画面で編集した原稿、既存テイクの試聴。
- 対応編集：候補から選び直す、旧原稿を検索して指定、対応を解除して新規にする、旧行を残す／削除する、追加位置を変更する。変更後は差分と確定順序を再計算する。
- フィルター：全件／変更／追加／削除／移動／対応要確認／無効。色だけに依存せず文字と記号を付ける。
- 最下部の固定操作欄：変更件数・未解決件数、「下書きを破棄」「台本を確定」。全体スクロールを発生させず、確定ボタンを常に画面の下部に置く。

対応が曖昧な行、対応の重複、順序の衝突を解決してから台本確定できるようにする。「旧行なし・新規として追加」をユーザーが選んだ行は未解決扱いにしない。

行の分割・複数行の結合も候補として表示できるが、自動で録音を複製・連結・切断しない。新しい行には旧テイクを参照候補として残し、既存音声の利用か再収録かを明示的に判断する。通常の1対1対応とは別扱いにする。

### 6. 音声の引き継ぎと再収録判断

| 差分 | 確定時の扱い |
| --- | --- |
| 本文不変・順番だけ変更 | 行ID・テイク・採用・読み上げ編集・無効状態を維持。位置と階層を更新 |
| Markdown装飾だけ変更し、読み上げ対象本文は完全一致 | 元Markdownの差分は表示し、音声と採用を維持 |
| 本文変更 | 行IDと既存テイクを維持。「原稿変更・音声要確認」を付け、旧採用音声を比較用候補として残す |
| 新規追加 | 新行IDを付ける。通常の初期オン／オフ判定を適用。有効なら未収録 |
| 無効行の一致・変更 | 無効を維持。変更がある場合の音声要確認も保持し、再有効化したときに表示 |
| 削除を確定 | 台本と出力から除き、音声・対応履歴は保管。復帰時は旧IDとテイクを再利用 |

変更行では、旧文・新文・音声を比較して「既存音声をそのまま採用」または「再収録」を選べる。台本画面の詳細でも録音画面でも同じ判断を行える。

- 「既存音声をそのまま採用」は、現行の原稿版に対する確認済みの採用として記録する。録音時の原稿を書き換えない。
- 「再収録」は以前のテイクを削除せず、再収録待ちにする。新テイクを採用したら確認待ちを解消する。
- まだ判断していない変更行を、自動的に確認済み扱いにはしない。旧採用は候補として保持し、現行版の採用は未確定にする。出力時には未採用の行として案内する。これにより出力は従来どおり「現在採用されている音声」を使える。
- 対応付けの解決と音声の再確認は別段階。台本は確定して録音へ進めるが、音声確認待ちは「録音（完了）」に含めない。

### 7. 録音画面で編集済みの原稿との衝突

元原稿と読み上げ用テキストを分離して維持する。

- 元原稿不変なら、句読点追加・漢字の読み替え等の読み上げ編集をそのまま残す。
- 元原稿変更かつ読み上げ編集なしなら、新しい元原稿を読み上げ用の初期値とする。
- 元原稿も読み上げ用テキストも変更されている場合は、旧元原稿・新元原稿・編集済み読み上げ原稿の3つを表示する。「新原稿を使う」「編集済み原稿を残す」「手動で調整」を選べる。自動上書きしない。
- 文中の一部だけを自動移植できそうな場合も提案にとどめ、残す読み上げ原稿をユーザーが確認する。

### 8. 読み確認・比較・結合出力との連携

- 元本文・読み上げ本文・音声hashを処理結果の依存先として持ち、どれに対する結果かを追跡する。
- 本文不変の移動では、読み確認・比較結果を維持する。本文変更時は、以前の認識結果・補正・比較を履歴に残して再確認対象にする。
- 古い文字位置に依存した補正を、新しい文章の同じ位置へ自動適用しない。旧結果は参照できるが、現行版の確定結果として扱わない。
- 工程3・4は従来どおり省略可能。変更行の既存音声を明示的に再採用すれば、再合成・再採点なしで出力へ進める。
- 結合出力の操作方式は変えない。確定後の有効原稿の順序と現行採用音声を使う。自動の分割単位は新しい階層から再計算する。
- 手動分割・ファイル名・ブロック別間隔は、保持された行IDに追従させる。境界の行を削除した場合や複数の境界が衝突した場合は、マージ確認に出力設定への影響も表示し、勝手に別行へ移植しない。

### 9. 確定の安全性と既存データ移行

- マージ開始時の保存世代と元ファイル版を記録する。確定前に台本や録音が更新されていたら、最新状態から再評価する。古い下書きで上書きしない。
- 対応・順序・有効状態・音声確認状態・出力境界の変更を1回の保存世代として確定する。失敗時は確定前の状態を保つ。
- マージ画面へ戻る／取消／アプリ再起動で、未確定の追加や削除を録音側へ漏らさない。下書きを保存する場合も確定データとは別にする。
- 旧プロジェクトには初回移行時に固定IDを割り当て、既存segment_id/take_idと音声ファイルは保持する。単一source_markdownは1つの元ファイルとして扱い、TXT等の追加行も別の取り込み元として管理する。
- 既存のsource_lineは移行時の手掛かりに限定する。重複文章や履歴のため対応が一意でない場合は移行確認へ出す。無効行と履歴の対応を推測で統合しない。
- 現行の保存世代復旧を利用できるように旧データを残す。新形式を旧版アプリが誤って書き込まないよう形式版を更新し、既存版の読み込み・移行を検証する。
- 既存の容量・原稿件数制限はマージ後の全体に対して確認し、上限超過は確定前に表示する。

### 10. 受入例

1. 100行の先頭へ2行追加：既存100行のテイクID・採用・無効状態を維持する。
2. 中央の1文字だけ変更：前後は不変、変更した1行だけ音声要確認になる。
3. 同じ「ありがとうございます」が複数存在：順序と前後の文で候補を絞り、曖昧なら選び直せる。
4. A/B/Cの3ファイルからBだけ新版を取り込む：A/Cへ削除・変更を発生させない。
5. 複数ファイルを追加して途中へ挿入：画面で決めた順番で反映し、重複箇所は対応を確認できる。
6. 無効行を含む版を更新：無効状態を維持し、再有効化すれば従来のテイクを参照できる。
7. 章の移動、大量追加・削除、分割・結合：自動提案が誤っていても対応を解除・修正でき、保存音声を消さない。
8. 変更行で旧音声を再採用：現行版の採用として出力できる。再収録を選ぶと旧テイクは残り、録音未完了になる。
9. 元原稿変更と読み上げ編集の衝突：編集済みテキストを上書きせず、3者を比較できる。
10. 確定直前の世代変更・保存失敗・キャンセル：旧台本とテイクの関係を壊さない。
11. 手動出力境界に使う行の削除：設定への影響を表示し、確認してから確定する。
12. 1920×1080／1280×720：差分一覧だけがスクロールし、台本確定ボタンは最下部に常時表示される。

### 11. 実装フェーズ案

A. 固定ID・元ファイル版・対応履歴・音声確認状態のモデルと既存形式移行。
B. 複数ファイル取り込み、対象選択、順序／元テキストによる対応候補作成と単体試験。
C. 差分マージ画面、手動対応編集、下部固定の台本確定、世代競合と保存失敗の試験。
D. 原稿変更時の音声再確認、読み上げ編集の衝突解決、工程3～5・出力境界への連携。
E. 旧録音を含むプロジェクトで先頭／途中／末尾追加・大量改訂・再有効化の通し試験とビルド。

各実装フェーズでコンパイル・関連試験・コミットを行う。0.0.2準備段階ではアプリコード・プロジェクト移行は未実施。

## 0. 事前確認と矛盾の整理

### 確定した方針

- 横4ペイン：ファイル一覧、内容表示・編集、差分確認、読み上げ対象。ファイル一覧のドラッグだけでファイル順を変更する。読み上げ行のドラッグは実装しない。

- 既存faster-whisperで録音終了後に認識。空台本を追加でき、空本文へ認識結果を自動入力する。

### 今回確認した追加の決定

2026-09-10に以下3点を質問し、全て「この案でよい」と回答を受領。要求書にも反映した。以下の提案には回答前の記録を含む。現在の採用判断はreqの「実装判断」を参照する。

1. **回答済み・確定**：一括承認・解除は選択中ファイル。台本確定は全ファイルで、未承認差分が残る間は不可。ファイル一覧に未承認件数を表示する。
2. **回答済み・確定**：元ファイル名がない既存プロジェクトは、録音を保った1つの「既存台本」へ包む。本文から元ファイルを推測して自動分割せず、明示的な対応付け後に分割する。
3. **回答済み・確定**：全ての新規録音テイクを認識し、空欄のみ読み上げ本文と台本下書きへ反映。確定済み本文・正解読みは更新しない。既存録音は自動一括認識しない。

以下は実装前の提案履歴であり、未回答事項一覧ではない。現在の既定動作はreqの「実装判断」を優先する。

- 新規ファイルは一覧末尾へ追加し、ドラッグで変更。再読込では既存位置と未指定ファイルを保持する。
- ファイル名は拡張子込みの名前で判定。異なるパスの同名は無断上書きせず衝突表示。同一バッチの重複名は取込確定前に解消。照合は拡張子込みの名前の完全一致、改名は新規として実装する。
- 空台本は一意な仮名を付け、通常のファイル台本と同じ順序管理に載せる。録音用空行には明示的な種別と所属ファイルを持たせる。
- 4ペインは幅可変の3境界、独立スクロール、右下固定の台本確定を維持。狭幅では本文を折り返す。ファイル名と操作が読める最小幅を実画面で決める。
- 100ファイル制限は廃止。大量登録は逐次取込・進捗・中止・表示の仮想化を検討する。2MBの全体制限をそのまま残して実質的な登録上限にしない。サイズ保護は1ファイル単位の資源管理として別に決める。

## 1. 保存と差分の構成

### 1.1 ファイル台本と3種類の状態

`domain.rs`へ型を追加する案：ファイル台本は不変source_id、照合用ファイル名、表示名、通常／空／移行由来の種別、確定本文、確定版、行所属を持つ。Projectに順序付きsource_id一覧を持つ。元パスは再読込照合の主キーにしない。

次を混ぜない。

1. **確定済み本文・順序**：台本確定が成功した時だけ更新。次の差分の基準。
2. **作業中本文・順序・読み上げ選択**：読込、手編集、ドラッグ、自動文字起こしで変更する下書き。
3. **承認フラグ**：特定の差分版に対する判断。本文そのものでも、永続的な台本確定でもない。

差分キーはsource_id・確定版・旧新内容・安定行IDを含む。再編集で内容が変わった差分の承認は失効させる。別ファイルに同じ文章があっても承認や行IDを共有しない。全解除は本文や読み上げ選択を消す操作にしない。

ファイル選択を変えても未確定本文を維持する。非同期の解析結果はproject_id・source_id・draft_revisionで照合し、古い返答を破棄する。下書き保存は確定本文と別に扱う。

### 1.2 保存と移行

`storage.rs`の世代管理とrevisionsを使用する。変更を一時Projectに組み立て、世代競合・所属・参照・未承認状態を検証して保存し、成功後にメモリと比較基準を切り替える。失敗時に画面だけ確定済みにしない。ファイル順・本文・行・出力参照を同じ確定操作で更新する。

保存形式は現行3からの拡張として次の形式番号を導入する計画。アプリ版0.0.2とは別物。旧版が新形式を誤解して書き戻さないようバージョン検査を確認する。0.0.1由来と既存0.0.2由来の複製fixtureで移行の再実行性を確認する。ユーザーの実プロジェクトには今回触れない。

ID・採用・音声hash・読み上げ編集・無効状態を維持し、ファイル追加や順序変更を理由に新しいSegmentを総生成しない。空ファイルも空配列として保存できる。既存のsource_markdownは必要なら確定済みファイル群から作る互換用派生値とし、二重の正本にしない。

### 1.3 差分と行の保持

同名ファイルを解決した後、そのファイル内で完全一致・文脈・既存固定対応を評価する。重複行の曖昧な対応を自動で録音へ結び付けない。差分は追加・削除を表示し、承認で確定予定プレビューへ反映する。承認で左の入力本文や確定基準を書き換えない。

既存R207/R208/R211の軽微変更維持・廃棄新規・編集保護は撤回されていない。差分行に承認以外の解除／却下を増やさず、必要な対応確認を詳細領域で扱う案とする。これらの行対応機能を今回省略する場合は別途範囲変更が必要。

全文の連結でファイル境界を失わない。ファイルごとに解析した結果へsource_idとファイル内順序を付けて全体順を作り、見出し階層や出力ブロックが意図せず次のファイルへ持ち越されないか確認する。

### ASRの実行・保存・競合対策

録音停止要求ではなく、最終音声の保存とhash確定後に投入する。ジョブはproject_id、source_id、segment_id、take_id、audio_hash、本文版、実行IDを固定する。結果保存は最新の同一プロジェクトへ検証して適用する。認識中のトリム・削除・プロジェクト切替・同じ空行への複数テイクでは古い結果を本文へ適用しない。

ASRのbusy/stopを録音から分離する。逐次キューを基本とし、録音要求を優先して認識を中断・後で再実行する方式を第一案とする。GPU有無・CPU負荷の実測で同時認識の可否を決める。音声が保存済みならASR失敗を録音失敗と表示しない。未設定・失敗・待機・完了を区別し、再実行可能にする。

認識結果をテイクとhashに結び付けて保持し、文字起こしを正解読み・補正の承認・採用音声の選択へ自動変換しない。空欄自動入力が競合したら候補だけ保存する。空白のみは空欄扱い、既存テイクは手動再認識を可能とする。本文は既存編集欄で修正できる。新規テイクの自動認識は既定で実行し、オン／オフの追加は今回の要求に含めない。

## 4. 重点的に改善する点

- **確定版と保存世代の混同を防ぐ**：録音やメモ保存のたびに台本比較基準が進まないようにする。
- **同名と同一行を区別する**：同名ファイルだから全文・全録音を無条件維持するのではなく、変更行は既存の行保持判断を通す。
- **空台本を文字列の空欄だけで管理しない**：安定IDと種別で、空でも登録・録音・保存できるようにする。
- **一括操作を取り違えない**：全解除で本文が消えたり、未選択ファイルに見えない変更が起きたりしないよう、対象と件数を表示する。
- **ファイル順と行IDを分離する**：並べ替えで録音の参照や出力ブロック境界が壊れないようにする。
- **認識を録音の成功条件にしない**：ASRが失敗しても音声は保持し、再実行できるようにする。

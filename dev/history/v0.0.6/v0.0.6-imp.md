## 0. 事前確認

### 0-1. 確認した仕様

| 論点 | 決定 |
|---|---|
| テイク移動 | 移動先は原稿一覧から1件選択し、末尾に新しい発話を作る。本文は移動元の確定本文を初期値とし、移動先では未採用にする |
| 音声編集 | 同一ウィンドウのモーダルへ前後トリム・途中カット・試聴・保存を集約する |
| 試聴条件 | 編集範囲の指紋を持ち、数値または線の変更後は編集後音声を再試聴するまで確定不可とする |
| 版・公開 | v0.0.6。署名済みMSIX作成、配布ページ更新、FTP公開、HTTP検証まで実施 |

### 0-2. 原因の切り分け

- `app.rs` が `script_draft` と `script_validate_draft` を同じ検証専用分岐で返すため、下書き保存RPCが実保存へ到達しない。
- UIの原稿一覧にある「確認済み」は差分承認済みを示し、バックエンドの確定成功と区別されていない。
- 同一本文の差分はLCSの一意でない対応を行番号へ戻すため、挿入された重複行と既存発話の所有関係が曖昧になる。
- 録音画面の編集状態はプロジェクト・発話IDだけをキーにし、同一発話のrevision更新を再同期条件に含めない。
- 現行トリムは1つの残存範囲だけを扱い、途中区間の除去、編集指紋、確定前試聴を持たない。

## 2. 要件別・実装方針

### R701～R705 原稿更新の安全性

- 検証RPCと保存RPCを分離し、下書き保存では保存世代を進める。
- 競合時はローカル下書きを保持し、再読込・退避に必要な比較情報をUIへ返す。
- 確定表示はバックエンドが返すrevisionと出力可能IDを正本にする。
- 重複行は安定した既存IDと単調な文脈対応を優先し、曖昧な追加行を新規とする。
- 対象外コンボを無効化し、録音画面のキャッシュをsegment revisionで破棄する。

### R706 採用取り消し

- `selected`だけを解除するRPCを追加し、テイク・メモ・文字起こしを保持する。
- 録音見出し右端に常時配置し、採用がない場合は無効化する。

### R707 音声編集

- 編集UIをモーダルへ移し、テイク欄には常時表示の編集入口だけを残す。
- 前後残存範囲と1組の途中除去範囲を一つの編集ドラフトとして扱う。
- 試聴用音声は一時生成し、現在の編集指紋と一致する試聴完了後だけ確定する。
- 確定時は新WAVを原子的に作成し、同じテイクIDのファイル・hash・長さを更新して編集値を初期化する。
- 編集後のhashに対して文字起こしを再投入する。認識失敗で加工済み音声を失わない。

### R708 合計時間

- 出力と共通の間隔決定関数から、採用音声の実効長・待ち時間・未採用件数を返す。
- 録音画面は保存済み設定、出力画面は編集中設定で即時再計算する。

### R709 テイク移動

- 移動先原稿IDだけを選ぶモーダルを追加する。
- 保存層で新発話作成、音声参照・付随情報移動、元採用解除を単一トランザクションにする。
- 新発話は移動先末尾、本文は移動元確定本文、未採用・要確認とする。

## 3. 影響範囲

保存形式の互換追加、台本保存、録音画面、音声加工、ASR再投入、出力時間計算、利用者ガイドへ影響する。既存録音、旧保存形式1～5、先頭末尾トリム、連続録音、出力設定を維持する。

### 3-1. データ差分と結果の例

| 操作 | 変更前 | 変更後 | 変えないデータ |
|---|---|---|---|
| 重複本文の間へ新規行を挿入 | `同文(id:A), 同文(id:B)` | `同文(id:新規), 同文(id:A), 同文(id:B)` | A/Bのテイク・読み・メモ |
| 採用取り消し | `selected: "take-1"` | `selected: null`, `needs_review: true` | `takes`, `take_notes`, `transcriptions` |
| 別原稿へ移動 | 原稿Aの発話に`take-1` | 原稿B末尾の新規発話に`take-1`、`selected: null` | 音声ファイル、hash、メモ、評価、文字起こし、確定原稿本文 |
| 途中2～3秒をカット | 5秒WAV、編集範囲0～5秒 | 0～2秒と3～5秒を連結した4秒WAV、編集値0～4秒 | テイクID。旧WAVは保存世代から参照できるため残す |
| 合計時間 | 音声10秒、先頭1秒、発話間0.5秒、末尾1秒 | 合計12.5秒 | 出力と同じ境界判定を使用 |

## 4. 実装で判明した追加対応

- `script_draft` が検証専用分岐で早期終了していたため、検証と実保存を分離した。保存完了時だけUIのdirty状態を解除する。
- 音声加工後のASR予約はプロジェクト保存後にロックを解放してから行い、ASR予約失敗で加工済みWAVを巻き戻さない。
- 出力処理と時間表示で待ち時間境界の判定を共通化し、表示と実出力の計算差を防いだ。

# v0.0.1 録音時ノイズ修正・検証補足（解決済み）

作成日：2026-09-09

解決確認：2026-09-12

本書は、v0.0.1で行ったWindowsマイク録音のプチプチノイズ対策について、調査根拠、実装内容、検証範囲を残す補足記録です。未完了の実装手順ではありません。実装全体は[v0.0.1実装記録](v0.0.1-imp.md)、後続の実機確認は[v0.0.2実装記録](../v0.0.2/v0.0.2-imp.md)を正本とします。

## 発生していた問題

2026-09-09時点の保存済み `capture.json` 23件では、アプリ内の `dropped_samples` は全件0でしたが、経過時間より保存WAVが96～1,458ms短く、平均差は約420msでした。使用endpointはWindowsの「リモート オーディオ」でした。

当時の実装はアプリ内リングバッファの欠落だけを見ており、WASAPI側のパケット不連続や時刻異常を十分に観測できていませんでした。欠落前後の波形を直接つなぐことと、入力形式が48kHz stereoと異なる場合にパケット単位でリサンプラー状態を作り直すことが、クリック音の原因候補でした。

## v0.0.1で実装した対策

- WASAPIの `data_discontinuity`、`silent`、`timestamp_error` を区別して集計。
- デバイス位置と時刻から欠落フレームを見積もり、転送リング・書込リングの欠落と分離して記録。
- 入力mix format、buffer／period、補償フレーム、経過時間を録音診断へ追加。
- 欠落区間へ無音を挿入し、境界を短いフェードでつないで急な波形段差を抑制。
- 長すぎる欠落値は診断を残して停止し、巨大なメモリー確保を防止。
- 変換が必要な入力では、パケットをまたいで状態と端数を保持する連続リサンプリングへ変更。
- 48kHz stereoの既存経路は不要な変換を避け、累積入力フレームから出力長を管理。
- 録音成功時は `capture.json`、途中失敗時は部分音声と `capture-failure.json` を保持。
- 入力不連続、欠落補償、時間差を、録音後の端部トリムとは別の診断として扱う。

## 自動検証

録音crateでは、小さいパケットをまたぐフェード、timestamp異常時に根拠のない推定を行わないこと、0フレーム不連続、フラグなしの位置欠落、欠落補償、累積リサンプリング時間、48kHz stereoの回帰を確認しました。

v0.0.1確定時はUI94件、Tauri44件、録音crate31件が成功し、外部環境を要する2件は対象外として記録しました。この件数は当時の結果であり、現在の試験件数ではありません。

## 実機確認と解決判断

v0.0.1確定時点では、同一マイクで30秒以上を5回録音し、Windowsサウンドレコーダーと比較する聴感確認は未実施でした。そのため、v0.0.1の自動試験だけでは音質合格としませんでした。

後続のv0.0.2終了時に、実マイク、連続録音、ASR負荷と音質を含む対象課題について、ユーザーから確認済み・問題なしとの報告を受領しました。この確認をもって本件を解決済みとします。

## 今後も維持する判断

- `dropped_samples = 0` だけで録音品質を良好と判定しない。
- 不連続を補償しても失われた発話内容を復元したとは扱わない。長い欠落は再録音を優先する。
- リモート接続の仮想endpointと物理マイクの結果を同一条件として一般化しない。
- 録音経路を変更した版では、自動試験と実マイクの聴感確認を分けて対象版のIMPへ記録する。

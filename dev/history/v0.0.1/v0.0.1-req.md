# 読みあわせ (ScriptSync) v0.0.1 要求定義

状態：2026-09-08のユーザー回答を反映。実装上の選択は計画案として区別する。

アプリ名は「読みあわせ (ScriptSync)」で確定。人間音声による局所読み補正と、自分の声による台本の発話単位録音・結合を行う。

## 目的

ユーザーの試聴所見では、橋／箸は漢字原文の方が自然で、市場はかな補正の効果がある。漢字を残すことで読み上げソフトの文脈判断を助け、実際の誤読だけをひらがなへ変える方式を検証する。すべてのモデル・文章で改善すると事前に断定しない。

## 初期版と後続

当分はv0.0.1で固定する。実装対象はR01～R09、R13～R15。R10（ルール出力）、R11（読点変更の比較）、R12（Talk編集ファイル出力）は当面見送りとし、R12の早期調査も今回の必須対象から外す。これらは保留要求として保持し、完成扱いや次版への自動移行はしない。R06/R09の音声比較・採点は継続する。

既存雨衣のAIだけによる選択補正は比較対象Dとして任意に利用する。新方式Cと同じものとして扱わない。キャラクター画像・動画・字幕生成、声の複製、Talk本体辞書の書換えは今回の目的外。

## 操作の流れ

台本録音：原稿登録 → 発話ごとに録音／取込 → 試聴・録り直し → 採用テイク選択 → 台本順の連続試聴 → 完成音声出力。読みの確定や合成サービス接続は不要。

原稿登録 → 人間音声の収録／取込 → 読みと原文の対応確認 → 正解版確定 → 原文音声生成 → AI音声の読み起こし → 差分確認と補正承認 → 再合成 → 匿名化した比較試聴・採点 → 原稿と音声・評価を保存。

人間の言い間違いやASR誤認識は原稿の読み誤りとは別に扱う。確認できない部分は保留にできる。全文一致でも同音異義語のアクセントは保証できない。

## 未確定事項と既定案

リポジトリ名・配置は `C:\develop\ScriptSync` で確定。Windows、Rust、Tauri v2、TypeScript、ローカルファイルを採用する。録音は提供サンプルをコピーして利用する。合成は `C:\develop\amekoro` の既存CLI／共通処理を介してCodex CLIとVoiSona Talkを利用し、接続・認証・合成を本プロジェクトで再実装しない。話者は当面デフォルトを使用する。ASRはローカル実行を第一候補に実測選定し、クラウド利用は音声送信先・保存条件を選択した場合の拡張とする。専門のアクセント教師データ作成や自動音声品質採点は初期版の必須条件にしない。

## v0.0.1差し込み修正：テイク評価・操作表示（2026-09-09）

- テイクメモの隣に評価を追加。未評価と0～100点の10点刻み11段階（合計12選択肢）から選び、変更直後に保存する。
- Fキーを示すボタン表記は半角括弧にする。
- テイク試聴は再生中に停止へ切り替え、最新テイクのF3も同じトグルにする。
- 開始・終了の数値入力にトリムバーを即時連動させる。
- 通常録音の開始(F1)と取り消し(F1)を同じ位置で切り替える。

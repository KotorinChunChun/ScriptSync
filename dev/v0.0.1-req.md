# 読みあわせ (ScriptSync) v0.0.1 要求定義

状態：実装前の整理案。出典はユーザーの今回のアイデアと雨衣の課題メモ。実装上の選択は計画案として区別する。

アプリ名は「読みあわせ (ScriptSync)」で確定。人間音声による局所読み補正を行う。

## 目的

ユーザーの試聴所見では、橋／箸は漢字原文の方が自然で、市場はかな補正の効果がある。漢字を残すことで読み上げソフトの文脈判断を助け、実際の誤読だけをひらがなへ変える方式を検証する。すべてのモデル・文章で改善すると事前に断定しない。

## 初期版と後続

v0.0.1の実装対象はR01～R09、R13。R12は早期の実現性調査までを初期版に含め、正式エクスポートは後続。R10、R11およびR12の正式出力は同じツールの後続要求としてこの一覧に保持する。初期版完成時もこれらを完了扱いしない。次版番号は着手時に決め、本書と次版資料の双方へ引き継ぎを記録する。

既存雨衣のAIだけによる選択補正は比較対象Dとして任意に利用する。新方式Cと同じものとして扱わない。キャラクター画像・動画・字幕生成、声の複製、Talk本体辞書の書換えは今回の目的外。

## 操作の流れ

原稿登録 → 人間音声の収録／取込 → 読みと原文の対応確認 → 正解版確定 → 原文音声生成 → AI音声の読み起こし → 差分確認と補正承認 → 再合成 → 匿名化した比較試聴・採点 → 原稿と音声・評価を保存。

人間の言い間違いやASR誤認識は原稿の読み誤りとは別に扱う。確認できない部分は保留にできる。全文一致でも同音異義語のアクセントは保証できない。

## 未確定事項と既定案

リポジトリ名・配置は `C:\develop\ScriptSync` で確定。Windows、Rust、Tauri v2、TypeScript、ローカルファイルを採用する。ASRはローカル実行を第一候補に実測選定し、クラウド利用は音声送信先・保存条件を選択した場合の拡張とする。人間録音はまず音声ファイル取込で実証し、続いてアプリ内録音を追加する。専門のアクセント教師データ作成や自動音声品質採点は初期版の必須条件にしない。

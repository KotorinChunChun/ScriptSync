### v0.0.1の二つの用途

1. 台本録音：発話ごとの自分の声を録音・録り直し・採用し、台本順に結合して完成音声を出す。録音サンプルのRustコードをコピーして基盤とする。

### 台本結合・出力の追加設計

初期の完成出力はWAVを標準とする。MP3は今回の必須条件にせず、必要になった時点でサンプルのエンコーダー利用を検討する。`src-tauri/src/assembly/` と `src/features/export/` を予定構成へ追加する。

- 発話順と採用take ID/hashを固定したExportPlanを作り、順序、入力形式、編集範囲、発話間の追加無音、出力形式を記録する。
- 発話ごとの前後トリムと追加無音を非破壊で指定できるようにする。既定は原音全体・追加無音0 ms。文中の間を自動短縮しない。連続試聴と出力に同じプランを使う。
- 未採用・失敗・破損・hash不一致の発話があれば完成出力を止め、該当行を示す。空行など読み上げない行は明示的に対象外とし、黙って飛ばさない。
- 録音サンプルの48 kHz stereo Float32を基準形式とし、取込音声は原音を保持した派生PCMへ変換する。結合は逐次処理し、長い台本を全量メモリへ載せない。
- 初期出力は48 kHz stereo PCM16 WAV。飽和・非有限値を検査し、必要な音量調整を明示する。WAVサイズ上限を事前検査し、超える場合は分割を案内する。
- ExportPlanの入力スナップショットから一時出力へ書き、完了検査後に新規ファイルとして確定する。原音や過去出力を上書きしない。出力中の採用変更は次の出力へ反映する。
- 音声とともに発話ID、採用take、出力上の開始/終了フレーム、条件hashをmanifestへ保存する。強制終了後は未完了出力を完成扱いにせず、同じプランから再実行する。

雨衣src内で見つかった結合処理はengine.pyの動画クリップ用FFmpeg連結であり、確認した音声CLIには台本take結合の公開コマンドがない。録音サンプルのWAV入出力・変換を再利用し、ScriptSync固有の採用順管理・非破壊編集・出力プランだけを追加する。

### 実装順序

P0の録音サンプル検証 → P1のコピー・保存・復旧 → P2の台本録音/取込・テイク採用 → P2の結合試聴・WAV出力を先行する。ASR・雨衣契約のP0調査は録音系の完了条件と切り分け、その後P3の誤読補正、P4の比較採点、P5の両用途の実証へ進む。

録音系の受入試験は、複数発話と複数テイク、採用変更、順序保持、未採用検出、形式変換、境界試聴、出力中断・再開を含める。強制終了から復元後も採用音声と出力manifestが一致することを検証する。各実装フェーズのビルド・適切な試験とコミットを維持する。既存の音声比較・採点（R06/R09）は対象内であり、今回見送る読点変更比較（R11）と混同しない。

追加の必須確認事項はない。ASR方式は実測、出力の細部は上記既定案で具体化する。

### 画面と操作

「原稿・収録」「読み確認・補正」「比較評価」の3画面と設定画面を設ける。左側に発話一覧と進捗、中央に選択発話、下側に再生操作を配置する。

1. 原稿を貼付け／TXT取込し、発話へ分割する。初期案は改行単位と手動分割・結合。原文とグローバル位置を保持する。
2. マイクを選んで録音、停止後に試聴し、使用するテイクを選ぶ。音声取込も同じtakeモデルに入れる。録音開始は明示操作だけとする。
3. ASRの生結果と確認用かなを分けて表示し、聴取・修正・原文範囲対応の確認後に正解版を確定する。
4. 固定話者条件で原文を合成し、実音声の読み差分を表示する。差分ごとに原文位置と双方の音声区間を確認して採用・却下・保留を選ぶ。
5. A=原文、B=全文かな、C=局所補正を同条件で生成する。匿名提示で読みの正確さと自然さを別々に採点し、保存・再開・出力する。

録音中は再生を止め、同一発話の原稿変更・マイク変更を抑止する。停止操作後は「保存中」を表示し、ファイル確定前に録音完了と表示しない。取り直しても以前の採用・正解を破棄せず、新テイクへの切替後に関連結果を再確認待ちにする。文字入力中に録音ショートカットが発火しないようにする。

### データモデルと復旧

既存 `docs/architecture.md` のUnicodeスカラー位置、原文ハッシュ、読み対応、補正区間、run/variant/rating契約を維持し、以下を追加する。JSONを保存の正本とし、初期版でSQLiteとの二重管理は導入しない。

| データ | 主な属性・制約 |
|---|---|
| Project | schema_version、ID、原稿版、発話順、保存世代 |
| Segment | 安定ID、原文版、原文区間。分割・結合後も旧テイクを削除しない |
| Take | ID、segment ID、原稿版、原音パス/hash、機器、形式、実時間、drop、品質、収録状態 |
| ReferenceRevision | 採用take ID/hash、確認済みかな、対応範囲、確定日時、版 |
| AudioDerivative | 元音声hash、変換設定、出力hash、編集範囲と時刻対応。原音と区別 |
| Job | ID、入力版/hash、条件hash、工程、状態、試行番号、エラー分類、成果物 |

作業フォルダには `project.json`、`revisions/`、`takes/<take-id>/`、`runs/<run-id>/`、`exports/` を置く。既存のrun配下のcase/variant/rating構造は維持し、projectから参照する。重複する音声の正本はtake ID/hashで特定する。

録音開始前にtake IDと開始記録を永続化し、`takes/<id>/pending.wav` に収録する（サンプルは.wav拡張子を必須にしているため）。停止→writer完了→WAV検査・hash→音声確定→台帳確定の順に処理する。途中失敗は回収候補として残す。起動時に開始記録・孤立WAV・保存世代を照合し、完了takeを復元、未確定音声は検査後にユーザー確認へ回す。破損WAVの完全修復は保証せず、可能な回収と失敗を区別する。

単一projectへの多重書込をロックで防ぐ。保存世代を残し、Windows上の置換・ディスク不足・強制終了を検証する。ファイルは新規作成で排他的に確保し、事前のexists検査だけに依存しない。復旧時も不正な相対パスやリンクによる作業フォルダ外参照を拒否する。

### Tauri境界と非同期処理

command案：`list_input_devices`、`start_recording`、`stop_recording`、`select_take`、`import_audio`、`play_audio_range`、`stop_playback`、`confirm_reference`、`start_transcription`、`start_synthesis`、`cancel_job`、`decide_correction`、`save_rating`。

UIはproject/segment/take/job IDを渡し、Rust側が保存パスと対象版を解決する。録音は専用workerで動かし、開始commandはjob IDを返す。進捗通知は間引いて表示し、通知欠落時も状態取得で復元できるようにする。worker終了を待つ間にUIや状態ロックを占有しない。録音状態は idle → starting → recording → stopping → finalizing → idle、失敗時は失敗結果を保存してidleへ戻す。二重開始と古いjobへの停止要求を拒否する。

ASR・合成も非同期jobとして管理し、完了時に入力版/hashを再検査する。原稿・採用take・正解読み・声条件の変更後に古い結果を上書き適用しない。古い成果物と採点は履歴として保持する。

### 認識・合成の判断

ASRはローカル第一候補を維持し、エンジンの採用はP0で決める。通常の漢字ASRからかなへ変換すると誤読を隠す問題があるため、サンプル追加によって解決済みとはしない。原文なしの音声認識と人間の手動確認を分離する。時刻不明はnull、曖昧な原文対応は保留とする。

合成は既存の雨衣CLI固定plan経路を維持し、EXE・設定の指定と実機契約確認を行う。A/B/Cは声・辞書・共通分割条件を固定する。原文とかな展開後の制限を両方検査する。認証・接続・生成・認識・品質評価の失敗を別に記録する。

## 設計判断

新ツールが録音・実発話照合・確認・評価を担当し、雨衣CLIを合成バックエンドとして利用する。CLIの既存AI選択補正は人間音声照合とは別経路である。声設定を一度固定してplan経由で合成することで、候補ごとのAI声設定変化を排除する。

最初は手動確認を含む一文の往復を完成させる。ASR結果だけから全自動補正する設計は採用せず、認識の信頼性を測定して候補生成の自動化範囲を決める。長文の一括制作は一文の状態・保存・再開が安定してから追加する。

開発プラットフォームはWindows上のRust 2024 edition + Tauri v2とする。WebView側はTypeScript + Vite、状態遷移・入力検証・原子的保存・外部プロセス実行はRust側へ置く。UIから外部EXEや任意パスへ直接アクセスせず、型付きTauri commandを境界にする。

## 台本構成・連続収録・分割出力の再設計（2026-09-09）

「台本を構成する → 順番に録音・採用する → 必要なら補正・比較する → 分割単位を決めて出力する」を基本フローにする。

上部の工程は次の5画面とする。

1. 台本
2. 録音
3. 読み確認・補正
4. 比較・採点
5. 結合・出力

各工程は直接クリックして移動可能にする。採用済みの音声があれば、読み確認・補正と比較・採点を飛ばして出力できる。左側はフィルターと折りたたみ可能な台本ツリーだけにし、台本追加・全体編集・履歴は「1 台本」へ移す。

### 2. Markdown原稿からの台本構成

読み込んだ元原稿を保持し、行単位で読み上げ対象を選択できる一覧を表示する。

| 内容 | 初期状態 | 読み上げ時の扱い |
| --- | --- | --- |
| 見出し | オン | 見出し記号を除き、章・節として管理 |
| 箇条書き・番号付き箇条書き | オン | 箇条書き記号を除く |
| 通常の文章 | オン | 文章を対象にする |
| コードブロック・表・画像 | オフ | 原稿には残し、読み上げから除外 |
| 空行・区切り線・コメント等 | オフ | 構造の区切りとして扱う |

行のクリックでオン・オフを切り替える。対象外の行も薄く表示し、後から戻せるようにする。太字等の装飾記号は除き、リンクは表示文字だけを使う。

「台本を確定」でオンの行から録音用の発話を作る。基本は1行＝1発話とし、見出しの章・節情報を各発話に持たせる。見出しを読み上げ対象から外しても、その章・節構造は維持する。

左ツリーは章・節単位で折りたためる構成とする。発話番号と文章を同じ行にスペース区切りで表示し、高さを圧縮する。クリックすると対応する原稿を表示する。

```text
▼ 第1章 はじめに
    001 はじめに
  ▼ 第1節 この資料について
      002 この資料について
      003 最初の説明文……
      004 次の説明文……
▼ 第2章 操作方法
    005 操作方法
```

### 3. 連続収録の標準動作

1. 台本確定後、最初の有効な発話を表示する。
2. 「録音開始」で収録する。
3. 「停止して保存」で前後無音を切り、各0.1秒を残して保存する。発話途中の無音は維持する。
4. テイクを試聴し、必要なら新しいテイクとして録り直す。
5. 「採用」で使用するテイクを確定する。
6. 次の有効な発話へ移動し、すぐ録音開始できる待機状態に戻す。
7. 最後の発話を採用したら「3 読み確認・補正」へ移動する。「結合・出力へ進む」操作も用意する。

前へ・後へは巡回させない。先頭の「前へ」、末尾の「後へ」は無効化する。

録音画面から「カーソル位置で分割」「次と結合」「結合対象外」を撤去する。原稿の編集は可能なままとし、読み上げテスト手順は原稿側の左半分へ配置する。右側のテイク一覧は上端から使えるようにする。

テイクカードは上段にテイク番号・採用状態・ラベルなしのメモ欄、下段に波形と赤い再生位置線、その右に試聴・採用・削除を配置する。秒数表示と青い時間バーは撤去する。波形左端を0秒、右端を保存済みテイクの終端に対応させ、切り落とした区間は描画しない。

削除確認にはブラウザ標準ダイアログを使わず、アプリ中央のモーダルを使用する。背景操作を止め、「キャンセル」「削除」を表示し、削除を確定した場合だけ実行する。

### 4. 操作不能と状態管理の見直し

会話中に示されたコードでは、操作中フラグが立った状態で画面を描画した後、フラグ解除時にボタンの無効化が解除されない経路が疑われる。状態取得の混雑だけでなく、画面側のロック解除を再現試験で確認する。原因の断定は再現・検証後に行う。

| 状態 | 許可する動作・復帰先 |
| --- | --- |
| 待機中 | 録音開始・試聴・採用・移動 |
| 録音中 | 停止保存・取り消し |
| 保存中 | 保存中表示。成功・失敗のどちらでも待機へ復帰 |
| 採用中 | 保存完了後、次の発話を待機状態で表示 |
| 削除確認中 | 中央モーダルだけ操作可能 |
| エラー | 理由を表示し、再操作可能な状態へ復帰 |

通信終了・失敗時の解除処理を共通化し、ボタンの有効・無効を現在の状態から決定する。バックエンドの長い音声処理中にも状態表示が応答できるよう、共有状態のロック範囲を見直す。

### 5. 元原稿・編集後原稿・録音原稿の対応

発話ごとに以下を保持する。

- 元Markdownの行と見出し階層
- 元の読み上げ原稿
- 編集後の読み上げ原稿
- 各テイクを録音した時点の原稿
- 採用テイクと、その録音時点の原稿

録音画面の原稿はフォーカス離脱時に保存する。句読点の追加、漢字からひらがなへの変更等を行っても元原稿との対応を失わない。変更していない発話も同じ仕組みで対応を保持する。

採用によって使用音声を確定する。かな読みの正解や比較採点まで自動確定した扱いにはせず、それらが未実施でも結合・出力を許可する。

### 6. 出力ブロックの構成と編集

#### 用語・操作の訂正

- 見出し1＝部、見出し2＝章、見出し3＝節、箇条書き＝項とする。本文やツリー、分割単位、間隔設定もこの対応で表記する。下記の旧章節表記より本訂正を優先する。

- 出力形式のプルダウン変更に合わせ、詳細パネルとファイル名プレビューの拡張子も連動させる。
- 境界の追加はハサミ（✂）、解除して結合はリンク（🔗）で表し、ツールチップ・アクセシブル名に操作内容を付ける。
- ブロック間に余白を作らず、行間の境界とホバー表示の位置を一致させる。
- 選択中は太い外枠と強調表示で明示する。背景の交互2色は維持する。
- 試聴は選択ブロックから開始し、続くブロックを順番に再生する。再生中のブロックを自動選択・スクロールし、再生中表示を付ける。停止操作と最後のブロックで再生を終了する。
- HTMLモックでは3秒ごとに再生対象を移す表示デモのみ提供する。実音声再生・ファイル変換は行わない。

#### 連続録音の追加設計

録音画面に「連続録音を開始」と「連続録音を終了」を用意する。開始を明示的に押した期間だけ、非アクティブ時にも働くF1～F4のグローバルホットキーを登録する。通常時は監視しない。全キーボード入力の記録は行わず、対象キーだけを扱う。

| キー | 動作 |
| --- | --- |
| F1 | 現在の発話の録音を開始。録音中・保存中の重複開始は無視 |
| F2 | 現在の録音を取り消す。同じ発話で待機 |
| F3 | 録音を停止して保存。同じ発話で試聴・採用待ち |
| F4 | 現在の発話の最新の保存済みテイクを採用し、次の発話へ移動。自動継続時は次の録音を開始 |

自動継続を連続録音の標準動作とする。保存中のF4、録音中のF4など前提を満たさない操作は実行せず、理由を状態表示に出す。キーリピートで複数実行しない。最終発話の採用後は次の録音を開始せず、監視を解除して読み確認・補正へ進む。「連続録音を終了」、プロジェクト切替、録音工程からの離脱、アプリ終了でもホットキー登録を解除する。終了操作は録音中なら録音を停止して保存し、次の録音を開始しない。F3は単独テイクの停止保存なので連続録音セッションは継続する。

キー登録に失敗した場合は監視開始済みと表示せず、失敗理由を示す。非アクティブ状態での収録、最終採用後・終了後にホットキーが解放されること、保存失敗・取消後の復帰を受入試験に含める。

結合・出力画面の上部に「分割単位」を横並びにする。

「全体で1ファイル」「部ごと（H1）」「章ごと（H2）」「節ごと（H3）」「発話ごと」

下部に台本を順番に表示し、出力ファイルごとに2色の背景を交互に使い、境界線で区切る。下位見出し単位でも上位見出しの境界は維持する。

分割編集は行の左端に設けた専用エリアで行う。行間の位置へカーソルを合わせると、本文幅に仮の境界線を表示する。クリックで境界を追加し、既存の境界をクリックすると解除して隣接ブロックを結合する。先頭・末尾の外枠は解除できない。原稿順は維持する。

行単位の選択、ドラッグ選択、「上のブロックと結合」「選択範囲を独立」「選択範囲の前で分割」は設けない。本文をクリックすると、その行が属するブロック全体を選択し、右側の詳細パネルにファイル名編集を表示する。ブロック別編集項目は原稿由来のファイル名と間隔設定とする。原稿表示は部・章・節・項の順に1階層につき全角スペース1文字相当を字下げし、通常の文章は所属階層に合わせる。

選択ブロックの原稿由来の名前だけを詳細パネルで編集可能にする。自由にまとめたブロックでは、先頭の見出しまたは発話から生成する。4桁連番・階層表記は固定部分として別段に表示し、編集欄と二段に分離する。拡張子も編集不可で出力形式に連動する。

```text
0001_第1部_はじめに.flac
0002_第2部_第1章_基本操作.flac
0003_第2部_第2章_応用操作.flac
```

### 7. 間・音量・形式・試聴

下部に全体の「既定の結合時の間隔」として以下の秒数入力欄を並べる。

| 設定 | 適用箇所 |
| --- | --- |
| 通常の発話間 | 同一ファイル内の発話間 |
| 部の区切り（H1） | 部境界をまたいで結合する箇所 |
| 章の区切り（H2） | 章境界をまたいで結合する箇所 |
| 節の区切り（H3） | 節境界をまたいで結合する箇所 |
| ファイル先頭 | 各出力ファイルの先頭 |
| ファイル末尾 | 各出力ファイルの末尾 |

右側の選択ブロック詳細には同じ秒数項目を設け、項目ごとに「既定／手入力」を選べるようにする。既定では数値欄を無効化してグレー表示し、全体の既定値の変更を即座に反映する。初めて手入力へ切り替えた時点の既定値を初期値とする。手入力から既定へ戻しても、その場で再度切り替える間はブロック別・項目別に直前の手入力値をメモリに保持する。永続保存には手入力が選択されている項目の値だけを含め、既定に戻した項目の一時値はリロード時に破棄してよい。ファイル先頭・末尾にも同じ切替を適用する。境界を結合した際は先頭側のブロック設定を適用し、分割後のブロック設定は開始原稿のIDで対応させる。

境界の間は加算せず、部・章・節・通常のうち該当する最上位の設定を使う。ファイルを分ける境界には発話間の設定を適用しない。

音量調整を保持し、全出力に共通の目標音量でノーマライズする。音量調整前、ノーマライズ後、間を含めた結合後、つなぎ目付近の試聴を可能にする。「ドラッグで残す区間を指定」は撤去する。画面下の共通プレーヤーは維持する。

出力形式の設計案はFLACを標準、WAVを選択可能とする。MP3・M4Aは今回の必須形式とはしない。出力完了後に「出力フォルダーを開く」を表示する。

1のツリーをクリックした場合は、中央の対応する元原稿行へ移動して強調する。オンオフの変更は中央の行操作で行い、ツリーで選択しただけでは変更しない。読み上げオフの構造も1では確認できるよう薄く表示する。2以降は確定済みの読み上げ対象だけを使う。

録音工程のツリーは短い原稿番号・冒頭文・未収録／未採用等の必要な状態だけを1行にまとめる。読み確認のバッジを録音工程へ出すなど、工程外の状態を混在させない。

### 3. フィルター・選択・状態の規則

- 各工程の初期値は「すべて」。作業できない原稿を勝手に消さない。3で採用音声がない原稿は表示し、必要な操作の横に「録音でテイクを採用」を案内する。
- 未採点は現在有効な比較に未入力の評価が残る原稿、再比較は原稿変更で比較結果が無効になった原稿とする。古い比較履歴だけで現在の作業を完了扱いにしない。
- フィルター、ツリーの開閉、スクロール位置は工程別に保持する。プロジェクトを変えたら初期化する。
- 2～4の選択原稿は引き継ぐ。選択原稿が移動先のフィルターから外れる場合は、その工程を「すべて」に戻して原稿を見失わないようにする。
- フィルターの結果が0件なら「該当する原稿がありません」と「すべて表示」を出す。項目が0件だからという理由だけでペインを消して幅を揺らさない。
- 連続録音で採用して次へ進む順番は、フィルター表示に関係なく確定原稿の順番とする。最後に先頭へ巡回しない。
- 5のブロック選択と2～4の原稿選択は別に保持する。出力中の再生追従で録音工程の選択を勝手に変えない。
- 1のツリーは編集中の元原稿、2～5は最後に確定した台本に対応する。再確定するまで下書きだけで既存テイクとの対応を変えない。

### 4. 前回設計との接続

ユーザー確認済みのキー操作・効果音・リロード対策は以下として引き継ぐ。トリミングは前回提示案を維持し、この設計と併せて実装対象としてレビューする。

- テイクの左右ハンドルで残す区間をドラッグ指定。元ファイルは保持し、保存済み範囲を試聴・採用・結合へ適用する。未保存の試聴は編集中の範囲を使う。
- 未変更時は「試聴・削除・採用して次へ」。変更時は「保存・試聴・削除」で、採用を隠す。保存成功後のみ未変更へ戻し、失敗時は編集範囲を保持する。未保存範囲があるテイクはF4でも採用できない。
- 未保存のトリミングを残して原稿／工程／プロジェクトを切り替える場合は、アプリ内確認で「保存して移動・破棄して移動・戻る」を選ぶ。開始・終了ハンドルは逆転させず、空の区間は保存しない。
- F1：収録中の未保存録音だけを取消して再録音。待機中は追加録音。保存済みテイクは消さない。保存処理中は完了後の追加録音要求を1件だけ保持する。
- F2：収録中のみ停止・保存。F3：保存済みの直前テイクを再生。F4：保存済みの直前テイクを採用して次へ。収録中・保存中のF3/F4は無効。通常ボタンは連続録音中に無効化し、状態によって使えないキーでは小さいエラー音を鳴らす。
- 録音開始、保存成功、次への移動、無効操作に効果音。開始音を鳴らしてから収録し、保存音はファイルの保存完了後、移動音は次の自動録音を始める前に鳴らす。音源・ライセンスは実装時に検索・確認して選定する（まだ選定していない）。
- 効果音の定義・出典・差し替え方は `dev/SOUND_EFFECTS.md`、キー割当と有効条件は `dev/SHORTCUT_KEYS.md` へ記録し、以降の定義変更でも更新する。
- F5、Ctrl+R、Ctrl+F5、Ctrl+Shift+Rによる再読み込みを抑止する。防ぎきれない再読み込みではバックエンド側で録音停止と途中音声保全を行い、キー監視・処理状態を整合させて操作可能な画面へ戻す。連続録音を自動再開しない。
- リロード復旧は「画面が再接続した際の状態確認」と「画面が失われた場合の監視」の両方で行い、フロント側の終了通知だけに依存しない。保存済みデータを削除しない。

## 終了延長・通常キー・テイク確定トリム（2026-09-09）

ユーザー依頼により前節の「元音声への範囲メタデータ保存」仕様を変更する。実装をテイク音声処理・トリムUI・親の録音制御に分担した。

- 停止保存の隣に「延長：数値 秒」。セッション初期値0秒、0～60秒。停止要求時にバックエンドが現在の収録の停止フラグだけを遅延設定する。連打で延長を積み増さず、取消後に次の録音を始めても前のタイマーでは止まらない。開始には待ち時間を追加しない。既存の前後無音除去は保存時に従来どおり適用するため、延長中の無音も除去対象になる。
- 通常録音ではアプリ内キーだけでF1開始／取消トグル、F2停止保存、F3最新試聴、F4最新採用して次へ。連続録音の既存グローバルキーと重複実行しない。保存済みテイクは取消しない。採用ボタンを強調色にし、F3/F4表示は最新テイクだけに付けた。
- 確定済みMarkdownの行オンオフはクリック時に即保存し、無効行を録音・前後移動・採用後の移動から除く。履歴にテイクを残し、同じ元行を再びオンにすると以前の編集原稿とテイクを戻す。全行オフも許可。新しいMarkdownの下書きは従来どおり確定時に反映する。
- テイクの開始・終了を0.01秒刻みの数値スピナーでも変更可能。試聴は指定範囲だけのWAVを再生し、再生位置でも終了上限を確認する。
- トリム保存は一意な新WAVへ物理的に切り詰めてからテイクのfile/hash/duration/peakを更新。開始・終了を全幅に戻し、状態と波形を再取得する。失敗時は元テイクを維持する。旧WAVは保存世代との整合のため残すが、元に戻すUIは設けない。録音済みラベルを総時間に置き換えた。

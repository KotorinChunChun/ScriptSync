### v0.0.1の二つの用途

1. 台本録音：発話ごとの自分の声を録音・録り直し・採用し、台本順に結合して完成音声を出す。録音サンプルのRustコードをコピーして基盤とする。
2. 誤読補正：採用音声から確認済みの正解読みを作り、合成音声との読み差分を承認して局所補正し、再合成・比較採点する。

原稿とtakeは共有するが、「録音の採用」と「正解読みの確定」は別の状態にする。録音用途はASR・Codex・Talkの未導入や接続失敗でも完結する。音声認識が未確定でも録音機能の実装を進められる。R10/R11/R12は当面保留、Talk編集形式の調査も必須工程から外す。バージョンはv0.0.1に固定し、段階ごとにタスクで進捗を管理する。

### 台本結合・出力の追加設計

初期の完成出力はWAVを標準とする。MP3は今回の必須条件にせず、必要になった時点でサンプルのエンコーダー利用を検討する。`src-tauri/src/assembly/` と `src/features/export/` を予定構成へ追加する。

- 発話順と採用take ID/hashを固定したExportPlanを作り、順序、入力形式、編集範囲、発話間の追加無音、出力形式を記録する。
- 発話ごとの前後トリムと追加無音を非破壊で指定できるようにする。既定は原音全体・追加無音0 ms。文中の間を自動短縮しない。連続試聴と出力に同じプランを使う。
- 未採用・失敗・破損・hash不一致の発話があれば完成出力を止め、該当行を示す。空行など読み上げない行は明示的に対象外とし、黙って飛ばさない。
- 録音サンプルの48 kHz stereo Float32を基準形式とし、取込音声は原音を保持した派生PCMへ変換する。結合は逐次処理し、長い台本を全量メモリへ載せない。
- 初期出力は48 kHz stereo PCM16 WAV。飽和・非有限値を検査し、必要な音量調整を明示する。WAVサイズ上限を事前検査し、超える場合は分割を案内する。
- ExportPlanの入力スナップショットから一時出力へ書き、完了検査後に新規ファイルとして確定する。原音や過去出力を上書きしない。出力中の採用変更は次の出力へ反映する。
- 音声とともに発話ID、採用take、出力上の開始/終了フレーム、条件hashをmanifestへ保存する。強制終了後は未完了出力を完成扱いにせず、同じプランから再実行する。

雨衣src内で見つかった結合処理はengine.pyの動画クリップ用FFmpeg連結であり、確認した音声CLIには台本take結合の公開コマンドがない。録音サンプルのWAV入出力・変換を再利用し、ScriptSync固有の採用順管理・非破壊編集・出力プランだけを追加する。

### 実装順序

P0の録音サンプル検証 → P1のコピー・保存・復旧 → P2の台本録音/取込・テイク採用 → P2の結合試聴・WAV出力を先行する。ASR・雨衣契約のP0調査は録音系の完了条件と切り分け、その後P3の誤読補正、P4の比較採点、P5の両用途の実証へ進む。

録音系の受入試験は、複数発話と複数テイク、採用変更、順序保持、未採用検出、形式変換、境界試聴、出力中断・再開を含める。強制終了から復元後も採用音声と出力manifestが一致することを検証する。各実装フェーズのビルド・適切な試験とコミットを維持する。既存の音声比較・採点（R06/R09）は対象内であり、今回見送る読点変更比較（R11）と混同しない。

追加の必須確認事項はない。ASR方式は実測、出力の細部は上記既定案で具体化する。

### 画面と操作

「原稿・収録」「読み確認・補正」「比較評価」の3画面と設定画面を設ける。左側に発話一覧と進捗、中央に選択発話、下側に再生操作を配置する。

1. 原稿を貼付け／TXT取込し、発話へ分割する。初期案は改行単位と手動分割・結合。原文とグローバル位置を保持する。
2. マイクを選んで録音、停止後に試聴し、使用するテイクを選ぶ。音声取込も同じtakeモデルに入れる。録音開始は明示操作だけとする。
3. ASRの生結果と確認用かなを分けて表示し、聴取・修正・原文範囲対応の確認後に正解版を確定する。
4. 固定話者条件で原文を合成し、実音声の読み差分を表示する。差分ごとに原文位置と双方の音声区間を確認して採用・却下・保留を選ぶ。
5. A=原文、B=全文かな、C=局所補正を同条件で生成する。匿名提示で読みの正確さと自然さを別々に採点し、保存・再開・出力する。

録音中は再生を止め、同一発話の原稿変更・マイク変更を抑止する。停止操作後は「保存中」を表示し、ファイル確定前に録音完了と表示しない。取り直しても以前の採用・正解を破棄せず、新テイクへの切替後に関連結果を再確認待ちにする。文字入力中に録音ショートカットが発火しないようにする。

### データモデルと復旧

既存 `docs/architecture.md` のUnicodeスカラー位置、原文ハッシュ、読み対応、補正区間、run/variant/rating契約を維持し、以下を追加する。JSONを保存の正本とし、初期版でSQLiteとの二重管理は導入しない。

| データ | 主な属性・制約 |
|---|---|
| Project | schema_version、ID、原稿版、発話順、保存世代 |
| Segment | 安定ID、原文版、原文区間。分割・結合後も旧テイクを削除しない |
| Take | ID、segment ID、原稿版、原音パス/hash、機器、形式、実時間、drop、品質、収録状態 |
| ReferenceRevision | 採用take ID/hash、確認済みかな、対応範囲、確定日時、版 |
| AudioDerivative | 元音声hash、変換設定、出力hash、編集範囲と時刻対応。原音と区別 |
| Job | ID、入力版/hash、条件hash、工程、状態、試行番号、エラー分類、成果物 |

作業フォルダには `project.json`、`revisions/`、`takes/<take-id>/`、`runs/<run-id>/`、`exports/` を置く。既存のrun配下のcase/variant/rating構造は維持し、projectから参照する。重複する音声の正本はtake ID/hashで特定する。

録音開始前にtake IDと開始記録を永続化し、`takes/<id>/pending.wav` に収録する（サンプルは.wav拡張子を必須にしているため）。停止→writer完了→WAV検査・hash→音声確定→台帳確定の順に処理する。途中失敗は回収候補として残す。起動時に開始記録・孤立WAV・保存世代を照合し、完了takeを復元、未確定音声は検査後にユーザー確認へ回す。破損WAVの完全修復は保証せず、可能な回収と失敗を区別する。

単一projectへの多重書込をロックで防ぐ。保存世代を残し、Windows上の置換・ディスク不足・強制終了を検証する。ファイルは新規作成で排他的に確保し、事前のexists検査だけに依存しない。復旧時も不正な相対パスやリンクによる作業フォルダ外参照を拒否する。

### Tauri境界と非同期処理

command案：`list_input_devices`、`start_recording`、`stop_recording`、`select_take`、`import_audio`、`play_audio_range`、`stop_playback`、`confirm_reference`、`start_transcription`、`start_synthesis`、`cancel_job`、`decide_correction`、`save_rating`。

UIはproject/segment/take/job IDを渡し、Rust側が保存パスと対象版を解決する。録音は専用workerで動かし、開始commandはjob IDを返す。進捗通知は間引いて表示し、通知欠落時も状態取得で復元できるようにする。worker終了を待つ間にUIや状態ロックを占有しない。録音状態は idle → starting → recording → stopping → finalizing → idle、失敗時は失敗結果を保存してidleへ戻す。二重開始と古いjobへの停止要求を拒否する。

ASR・合成も非同期jobとして管理し、完了時に入力版/hashを再検査する。原稿・採用take・正解読み・声条件の変更後に古い結果を上書き適用しない。古い成果物と採点は履歴として保持する。

### 認識・合成の判断

ASRはローカル第一候補を維持し、エンジンの採用はP0で決める。通常の漢字ASRからかなへ変換すると誤読を隠す問題があるため、サンプル追加によって解決済みとはしない。原文なしの音声認識と人間の手動確認を分離する。時刻不明はnull、曖昧な原文対応は保留とする。

合成は既存の雨衣CLI固定plan経路を維持し、EXE・設定の指定と実機契約確認を行う。A/B/Cは声・辞書・共通分割条件を固定する。原文とかな展開後の制限を両方検査する。認証・接続・生成・認識・品質評価の失敗を別に記録する。

## 設計判断

新ツールが録音・実発話照合・確認・評価を担当し、雨衣CLIを合成バックエンドとして利用する。CLIの既存AI選択補正は人間音声照合とは別経路である。声設定を一度固定してplan経由で合成することで、候補ごとのAI声設定変化を排除する。

最初は手動確認を含む一文の往復を完成させる。ASR結果だけから全自動補正する設計は採用せず、認識の信頼性を測定して候補生成の自動化範囲を決める。長文の一括制作は一文の状態・保存・再開が安定してから追加する。

開発プラットフォームはWindows上のRust 2024 edition + Tauri v2とする。WebView側はTypeScript + Vite、状態遷移・入力検証・原子的保存・外部プロセス実行はRust側へ置く。UIから外部EXEや任意パスへ直接アクセスせず、型付きTauri commandを境界にする。

## GUIの実装単位

左にケース一覧と進捗、中央に原文・確認済みかな・補正差分、下に人間／原文音声／補正音声の再生操作を置く。候補ごとに採用・却下・保留を持ち、原文位置と対応音声区間を表示する。別の評価画面では候補名を伏せ、採点後に表記を開示する。録音デバイスは選択したものを使用し、録音中・停止・保存状態を表示する。

操作中の原稿変更は新リビジョンを作り、古いワーカー結果を新原稿へ適用しない。音声再生成後の採点は別音声ハッシュへ紐付ける。停止・失敗後も保存・再開できるようにする。1280×650と拡大表示、キーボード操作、長文の表示、実再生を確認する。

## 後続機能の具体化

R11：Cの採用済み表記を固定し、読点なし／追加ありを比較。声設定・かな補正を同時変更しない。

R10：評価から語＋文脈＋話者名／版＋辞書条件に限定したルール候補を生成。根拠run/rating、反例、draft/approved/rejected、版を保持し、未使用文で検証した承認済み候補をプロンプト用ファイルへ出力する。初期連携はファイル出力とし、雨衣内部のプロンプトを勝手に変更しない。未採点・不明条件からルールを採用しない。

R12：導入済みTalkで作成した最小の1発話ファイルを基準に、正式に扱える形式を確認する。読み・話者・速度・スタイル・アクセント・間・音素長の保持表を作る。開く→編集→保存→Talk再起動→再読込→再合成が通るまで対応済みにしない。形式未確定時に独自JSONをTalkプロジェクトと呼ばない。取得できる解析データは合成ジョブ削除前のmetadataから保存する。必須編集出力に失敗した場合はWAV成功と分けて部分成功を示す。

# 読みあわせ (ScriptSync) v0.0.2 要求定義

状態：実装準備済み・未着手。ユーザーの複数Markdown対応と再設計依頼から切り出した要求。実装上の候補や確認ルールの詳細は [実装計画](v0.0.2-imp.md) に分離する。

基準版：v0.0.1、確定コミット `2ac26d9`、タグ `v0.0.1`。0.0.1の録音・テイク編集・出力機能を維持し、台本の取り込みと既存音声の対応付けを拡張する。

## 要求と受入条件

| ID | 要求 | 受入条件 |
| --- | --- | --- |
| R201 | Markdownを複数ファイルまとめて、または後から追加して読み込める | ファイルの追加と取り込み順を確認でき、既存データを無断で置換しない |
| R202 | 元テキストと順番を用いて既存原稿との対応を提案する | 先頭・途中への挿入で後続原稿の音声対応がずれない。行番号だけでは対応しない |
| R203 | 対応付けをユーザーが修正できる | 新旧対応を表示し、候補変更・対応解除・新規扱いの指定ができる |
| R204 | 少数文字の変更から大量増減・移動まで差分を確認できる | 変更前後の本文、追加・削除・移動、曖昧な対応を確認してから反映する |
| R205 | 先頭・末尾・途中への追加に対応する | 確定する挿入位置と順序が差分画面でわかり、指定した順で反映される |
| R206 | 無効状態を維持する | 対応する無効行を再取り込みしても無効のまま。既存音声を保持して再有効化できる |
| R207 | 既存録音・採用との対応を維持する | 本文不変の行ではテイクと採用を保持。本文変更時も旧テイクを削除しない |
| R208 | 変更行の再収録判断を支援する | 変更前後と旧音声を比較し、既存音声の再採用または再収録を選べる。未確認の変更行を識別できる |
| R209 | 「行を確認」を「マージ」に変更する | 取り込みデータを即時確定せず、対応と差分を確認する操作になる |
| R210 | 「台本を確定」を画面最下部へ移す | 原稿一覧が長くても確定操作が見え、確認した内容だけを一括反映する |
| R211 | 録音画面で編集した読み上げ原稿も保持する | 元原稿との対応を失わず、取り込みによって句読点や読み替えを勝手に上書きしない |
| R212 | 読み確認・補正、比較・採点との整合を保つ | 変更された原稿に古い文字位置の補正や比較を誤適用しない。工程3・4は省略できる |
| R213 | 現在の採用音声を結合出力する | 確定した順序・有効状態・採用を反映し、既存の出力操作を維持する |
| R214 | 既存プロジェクトと保存済み音声を保全する | 0.0.1データを読み込め、対応確認や保存に失敗しても確定済みデータを壊さない |

## 範囲

台本取り込み・差分マージ・対応修正が中心。録音／読み確認／比較／出力には原稿変更との整合に必要な修正を行う。録音エンジンや出力操作の全面再設計は本要求に含めない。

## 計画上の提案と区別

固定ID、追加／新版更新／部分統合の取り込み方式、LCSによる候補推定、音声確認待ちの状態、保存形式の版更新はAIによる実装計画。ユーザー要求そのものの引用ではない。詳細と受入例は実装計画を参照する。

## 実装開始条件

要求IDと計画・タスクの対応が揃っていること。既存プロジェクトの移行は複製した試験データで検証する。実装開始の指示があるまでは、アプリコード・保存形式・実行時バージョンを変更しない。

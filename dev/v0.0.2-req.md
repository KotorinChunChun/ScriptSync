# 読みあわせ (ScriptSync) v0.0.2 要求定義

状態：実装準備済み・未着手。2026-09-09の補足を反映。基準版はv0.0.1（ca0c954、タグv0.0.1-final）。[実装計画](v0.0.2-imp.md)と[進捗](v0.0.2-task.md)を併用する。

## 要求と受入条件

| ID | 要求 | 受入条件 |
| --- | --- | --- |
| R201 | Markdownを複数同時または追加で読み込める | 入力の結合順を確認でき、確定前に既存データを変更しない |
| R202 | 内容を基準に照合する | 元テキスト、前後関係、階層を使い、行番号・ファイル名・パスに依存しない。取り込み元名の永続管理は不要 |
| R203 | 対応と変更の扱いをユーザーが指定できる | 「既存行を維持」「旧行を廃棄して新規作成」、対応解除、新規追加を選べる |
| R204 | 少数文字変更・大量増減・移動を差分表示する | 旧文と新文、対応先、採用・テイク数、アーカイブ予定が確定前にわかる |
| R205 | 新原稿の順序へ並べ替える | 先頭・途中・末尾追加、行の上下入れ替えに対応し、旧順序を強制しない |
| R206 | 維持する行の無効状態を保持する | 軽微変更・移動でも無効を維持し、再有効化時に旧テイクを使える |
| R207 | 軽微変更の行は対応をつないで現状維持する | 同じ行ID・テイク・採用・編集済み読み上げ原稿を保持。変更は表示し、ユーザーが維持の判断を確定する |
| R208 | 明らかな変更は旧行をアーカイブして新規行にする | 旧行と音声を廃棄済みとして保持。修正後は別ID・テイク0件・採用なしで開始し、旧テイクを引き継がない |
| R209 | 「行を確認」を「マージ」に変更する | 対応候補の作成・確認・再評価を行い、即時反映しない |
| R210 | 「台本を確定」を最下部に固定する | 長い一覧でも常に見え、未解決を確認したうえで一括反映する |
| R211 | 録音画面の読み上げ編集を保護する | 既存行維持では編集を勝手に上書きせず、旧元原稿・新元原稿・編集済み本文を比較して解決できる。新規置換は新原稿から開始する |
| R212 | 読み確認・補正・比較との整合を保つ | 古い文字位置の補正を新原稿に誤適用しない。工程3・4は省略可能 |
| R213 | 新順序と現行採用音声を結合出力する | アーカイブは出力対象外。新規未収録行は未採用として扱う。従来の出力操作を維持 |
| R214 | 移行・保存失敗で既存データを壊さない | 0.0.1から複製データで移行でき、確定失敗・取消では旧台本と音声を保持 |
| R215 | 録音画面から廃棄済み行を確認できる | 「廃棄された行を表示」でアーカイブを表示し、旧原稿確認・音声再生・完全消去ができる。通常の収録・完了判定から除外 |
| R216 | 手動対応を起点に差分を再評価する | ユーザーが示した新旧ペアを固定し、再評価で解除・上書きしない。明示的な変更・解除まで保持する |
| R217 | 対応線が交差する行移動を許容する | 複数の手動対応が旧順序と逆でも保持し、残りを再照合して最終的に新原稿順に並べる |

## 補足の優先事項

本文が変わった全行を一律に「旧テイク付きの音声要確認」にする旧案を置き換える。軽微／明らかな変更の自動判断は候補提示にとどめ、台本作成時にユーザーが維持か廃棄・新規かを選ぶ。1文字でも数値・否定など意味が変わる場合があるため、文字数だけで決めない。

元ファイルの識別・版管理を前提にしない。複数の入力は内容を一つの新原稿として扱い、ファイル名が違っても同じ内容なら同じ候補を得られるようにする。

## 範囲と開始条件

台本マージ、録音画面のアーカイブ管理、関連工程の整合を対象とする。録音エンジンと出力操作の全面改修は含めない。固定ID、照合アルゴリズム、下書き保存、完全消去の内部処理は実装計画で具体化する。

今回の補足は設計変更。アプリコード・保存形式・実行時バージョンは、実装開始の指示までは変更しない。

基準を差し込み修正込みのv0.0.1最終完成版（タグv0.0.1-final、実装ca0c954）へ更新。0.0.2の実装開始を意味しない。

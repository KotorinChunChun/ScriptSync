## Web送信と権限の調査

デスクトップ側 `src-tauri/src/cloud_upload.rs` の `web_token()`、`encrypted_zip()`、`upload_web_with()` と、連携先ローカルソース `C:/develop/dev-k.sakura.ne.jp/www/tools/scriptsyncweb/api.php`（36～55、81～109、114～125行付近）を照合した。Web側は変更していない。

1. 選択原稿の確定版から交換ZIPを作る。
2. HNと6桁キーからPBKDF2-SHA256で認証トークンを生成し、ZIPをキーでAES-256暗号化する。
3. HTTPSで `api.php` に `start` → 512KiBずつ `chunk` → `finish` をPOSTする。
4. PHPがHNに対応するトークンを照合し、自身のOS権限で `storage/` へ保存する。
5. Web画面で同じHN・キーを使って取得する。保存期限は24時間、ZIP上限100MiB。HN数、保存件数、総容量、認証試行にも上限がある。

利用者にFTPアカウントやサイト編集権限は不要。サーバー管理者がPHPへ保存領域の書込権限を与え、APIが送信を受け付ける仕組みである。任意のWebサイトへアップロードできる機能ではない。

現行APIは未登録HNの場合、最初の `start` で登録を作成する。事前の管理者承認や利用者の許可リストは実装されていない。既存HNには一致するキーが必要。Originが付いている場合だけ同一ホストを検査し、RustからのAPI通信も受けられる構造である。Origin検査は利用者の認可の代わりではない。

結論：クライアントとAPIのコード上は送信可能。ただし、公開サーバーがこのローカルソースと同一か、現在のPHP書込権限・容量・通信状態は未確認。公開URLのWeb取得は失敗し、pwshのHTTP取得もソケットアクセス制限で失敗した。実送信やサーバーデータ作成は行っていない。v0.0.4文書にも実送信未検証と記録されている。

Web送信を限定利用者だけに許可する要件を追加する場合は、別途サーバー側の認可設計が必要。今回のデスクトップUI整理には含めない。

## 追加調査：録音・再生・Codex CLI

### 既定録音デバイスの不具合（コード上で原因確認）

`src/settingsView.ts` はWindows既定を空文字で保存する。`src-tauri/src/app.rs` の録音開始は `capture_endpoint` をそのまま `MicrophoneRecordingRequest::new()` へ渡す。`crates/scriptsync-recorder/src/windows/microphone_recording.rs` の検証は空IDを「マイクのEndpoint IDを指定してください」で拒否する。既定IDへの変換が欠けており、ユーザーの再現条件と一致する。

一方 `src-tauri/src/native_playback.rs` は既定デバイス解決用の `resolve_endpoint_id` と `DEFAULT_CONSOLE_ENDPOINT` を利用する。共通基盤 `windows/devices.rs` の既定指定は `default://console`。空文字のまま渡しても共通基盤は既定と解釈しない。

録音開始はテイクを先に作成・保存し、非同期処理の失敗時には `status = "failed"` として警告へエラーを入れて再保存する。このため録音開始に失敗してもテイクが残る。

### 再生デバイス

`app.rs` の `playback_play` は設定の `render_endpoint` を `native_playback.play()` に渡す。`src/nativeAudio.ts` は登録済み音源のHTML再生をネイティブへ接続する一方、未登録音源は元のHTML再生へ流す。`src/soundEffects.ts` の `new Audio()` は別経路のため、全再生が設定に従うとは保証できない。既存テイク再生そのものが設定を無視するかは実機で未確認。

### Codex CLIとfaster-whisper

`src-tauri/src/asr_runtime.rs` → `tools/asr/transcribe.py` を確認。直接方式はPythonからfaster-whisperを実行する。Codex方式はPythonから `codex exec` を起動し、専用MCPツール `transcribe_current_take` 経由で同じローカルfaster-whisperを実行する。ツールが書いた認識結果を採用し、CLIの自由文出力は採用しない。プロンプトは本文書換えを禁止している。

したがって現行実装にはCodexによる音声前処理・認識結果後処理はなく、別の認識エンジンにもならない。CLI経由では認識テキストがCodexへ渡る。今回の要件は最初に直接／CLI経由を選べる説明整理とし、新しい補正処理は未承認の機能として追加しない。これは当該アプリ実装の調査結果であり、Codex製品全体の能力の説明ではない。

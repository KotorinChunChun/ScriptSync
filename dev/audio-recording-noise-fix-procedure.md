# 録音時のプチプチノイズ対策 修正手順書

作成日: 2026-09-09  
対象: ScriptSync の Windows マイク録音（WASAPI shared event）

## 1. 目的と完了条件

録音した人声へランダムに混入する「プチプチ」ノイズをなくす。Windows サウンドレコーダーで再現しないため、端末全体ではなく ScriptSync の録音経路を修正対象とする。

完了とするには、同一マイク・同一環境での複数回の実録音において、以下をすべて満たすこと。

- 聴感でクリック／プチプチ音がない。
- 保存音声の長さと録音経過時間の差が許容値内である。
- WASAPI の不連続、リングバッファ溢れ、変換エラーを検出・記録し、無通知で音声をつなげない。
- 既存の録音、停止、キャンセル、WAV 保存、音量表示の動作を壊さない。

## 2. 調査で確定した事実

2026-09-09 時点の保存済み `capture.json` 23件を確認した。

- 全件の有効な録音方式は `wasapi_shared_event`。
- 画面へ返す `dropped_samples` は全件 0。
- それにもかかわらず、経過時間より WAV の音声長が 96～1,458 ms 短い。平均差は約420 ms。
- 例: 経過時間 22,483 ms に対して、録音WAVは 21,474 ms。
- 使用エンドポイントは Windows の「リモート オーディオ」。

したがって、アプリ内リングバッファ溢れだけを監視する現状では、WASAPI 側で発生するパケット不連続・欠落を検出できていない。欠落した前後の波形を無加工で連結すると段差が生じ、クリック音になる。

また、入力形式が内部形式（48 kHz stereo）と異なる場合、現在の線形リサンプラーは WASAPI パケット単位で変換状態を作り直す。パケット境界の補間連続性を保証しないため、第二のクリック発生源となる。

## 3. 修正の方針

優先順位は次のとおりとする。

1. WASAPI パケットの不連続を正しく検出・記録する。
2. 不連続区間を無音または短い補間で明示的に埋め、波形の段差を抑える。
3. 変換が必要な入力では、パケットをまたいで状態を保持するストリーミングリサンプラーを使う。
4. 利用者へ品質警告を表示し、問題のあるテイクを無自覚に採用させない。

WASAPI の shared event 経路を直ちに exclusive mode へ変更しない。互換性低下と端末依存の失敗を避け、まず shared mode の欠落処理と観測可能性を改善する。

## 4. 実装手順

### フェーズ A: 欠落の観測を追加する

- [ ] `crates/scriptsync-recorder/src/windows/wasapi_capture.rs` で、`read_from_device` が返すパケットフラグの `data_discontinuity` を取得する。
- [ ] `silent`、`timestamp_error` と区別して、パケット不連続回数・不連続フレーム数・最終発生時刻を録音セッションで集計する。
- [ ] `MicrophoneRecordingReport` と `capture.json` に上記の値、実入力の mix format（sample rate、channels、sample format）、WASAPI の buffer/period 情報を追加する。
- [ ] アプリ内転送リングの溢れ、writer リングの溢れ、WASAPI パケット不連続を別々に記録する。ひとつの `dropped_samples` に混ぜない。
- [ ] `src-tauri/src/app.rs` のテイク警告へ、不連続の回数・時間を含める。

### フェーズ B: 不連続区間を安全に処理する

- [ ] パケットに不連続フラグが付いた場合、直前の出力フレームと現在の先頭フレームを直接つながない。
- [ ] 欠落フレーム数が取得できる場合は、その長さの無音を挿入する。取得できない場合は、タイムスタンプまたは期待フレーム位置から推定し、推定値であることを記録する。
- [ ] 無音挿入の前後に 5～10 ms のフェードアウト／フェードインを適用する。発話全体へのノイズ除去や自動ゲートは行わない。
- [ ] 長い欠落（例: 100 ms超）は音質を「自動修復済み」と扱わず、再録音を推奨する警告を出す。
- [ ] 欠落時間が 0 であっても、パケット不連続を検出した事実は `capture.json` に残す。

### フェーズ C: リサンプリングを連続化する

- [ ] `crates/scriptsync-recorder/src/windows/device_format.rs` のパケットごとの `resample_interleaved_linear` 呼び出しを、状態を保持する変換器へ置き換える。
- [ ] 変換器は、前パケット末尾のフレーム、入力位置の端数、チャンネル変換状態を保持する。
- [ ] 48 kHz stereo 入力は変換せず、現行どおりの経路を通す。
- [ ] 44.1 kHz mono、44.1 kHz stereo、48 kHz mono、48 kHz stereo の連続正弦波をランダムなパケット長で渡し、境界で不自然な振幅跳躍がないことを単体試験化する。
- [ ] 出力フレーム数はパケットごとの丸めではなく、累積入力フレーム数に対して管理する。長時間録音で時間が徐々にずれないことを確認する。

### フェーズ D: 録音制御・表示を整える

- [ ] `MicrophoneRecordingReport` の記録値から、実時間・保存フレーム数・挿入した補償フレーム数の関係を検査する。
- [ ] WAV の長さが経過時間から大きく外れる場合は、録音成功ではなく「要確認」のテイクとして保存する。
- [ ] テイク一覧に「WASAPI不連続」「リングバッファ欠落」「補償した無音時間」を区別して表示する。
- [ ] 既存の録音終了後の端部トリム処理は、録音中の不連続処理と混同しない。端部トリムは WAV 完成後、不連続補償はキャプチャ中に実施する。

## 5. テスト手順

### 自動試験

- [ ] WASAPI フラグを模したパケット列を入力し、不連続が report に記録される試験。
- [ ] 欠落時にフェード付き無音が挿入され、出力が有限値・ステレオフレーム境界を保つ試験。
- [ ] リサンプラーの連続性試験。パケット境界の差分を通常波形の許容範囲内とする。
- [ ] 長時間相当の入力で、累積出力フレーム数が理論値と一致する試験。
- [ ] 48 kHz stereo の既存経路がサンプル値を変更しない回帰試験。
- [ ] `cargo fmt -- --check`、`cargo test --manifest-path src-tauri/Cargo.toml --lib`、関連 crate の `cargo test` を実行する。

### 実機試験

同じ「リモート オーディオ」エンドポイントで、Windows サウンドレコーダーと ScriptSync をそれぞれ録音する。各条件で最低 5 回、30 秒以上の連続発話を収録する。

- [ ] ScriptSync の各 `capture.json` に不連続・欠落・mix format が記録される。
- [ ] 保存WAVの長さと経過時間の差を記録する。
- [ ] ヘッドホンで、発話中にクリック音がないことを人が確認する。
- [ ] 不連続を意図的に起こした場合、クリックとしてつながらず、警告が表示されることを確認する。
- [ ] Windows サウンドレコーダーとの差異を、録音形式・入力デバイス・Windows の音声拡張機能の有無とともに記録する。

## 6. 合格基準

通常の実機録音では、以下を満たした場合に合格とする。

- 5回以上の30秒録音で、聴感上のプチプチ音が 0 回。
- ScriptSync が検出した WASAPI 不連続は 0 回、または発生時に補償時間と要再録音警告が記録・表示される。
- 保存音声長と経過時間の差は、開始／停止時のバッファ処理を除き 100 ms 以下を目標とする。
- `dropped_samples = 0` だけで品質良好と判定しない。

## 7. 注意事項

- 「リモート オーディオ」はリモート接続経由の仮想エンドポイントであり、物理マイクと同じ挙動を前提にしない。ただし、Windows サウンドレコーダーで良好なら、ScriptSync 側で不連続を見落としてよい理由にはならない。
- 欠落を補間しても、失われた発話内容そのものは復元できない。長い欠落は再録音を優先する。
- この修正は録音品質の改善を対象とし、既存テイクを一括変換・上書きしない。

# 読み上げテスト（ここから開始）

目安：録音のみ10～15分、読み補正の基本確認20～40分。実際の所要時間を記録してください。まず01だけで構いません。

## 起動

ビルド済みの `C:\develop\ScriptSync\src-tauri\target\release\scriptsync.exe` を起動します。開発起動はPowerShell 7で以下を実行します。

```powershell
cd C:\develop\ScriptSync
npm run tauri dev
```

「新しいプロジェクトを作成」で保存先と名前を指定して `.scriptsync` を作成します。後から「開く」ではこのファイルを選択します。同名の `.scriptsync.data/` は一緒に保持します。TXTやMarkdown、保存先の親フォルダーをプロジェクトとして開くことはできません。

工程1「台本」の左ペインで「Markdownを読み込む」から `01-recording.txt` を選びます。0.0.2開発版では中央で各追加を承認し、右で読み上げ対象を確認して「台本を確定」を押します。TXTは1行1発話です。テスト台本を挿入する専用の折りたたみUIはありません。

## 1. 自分の声を録音する（CLI側の音声合成エンジン・ASR不要）

1. 01の4行が順に表示されることを確認。Windowsの既定入力マイクを設定し、1行目を選び「● 録音開始」。本文だけを普通の声で読み、「■ 停止して保存」。保存時に前後の無音が切られ、各0.1秒だけ残ります。試聴し、音割れ・プチプチ音・途切れ・音量・語頭と語尾を確認して「採用して次へ」。
2. 2行目を2回録音。Take 1とTake 2を聞き比べ、良い方を採用。メモに理由を記録し、フォーカスを外して保存します。旧テイクが消えないことを確認。
3. 3行目は録音開始後と発話後に1秒ほど無音を入れて録音。保存後の長さが発話の前後各0.1秒程度になり、途中の無音は残ることを確認します。全行の採用後、工程5「結合出力」で発話間の既定間隔を0.30秒にして、つなぎ目を試聴します。語頭・語尾を切らないことが合格条件です。
4. 4行目を録音・採用。工程5「結合出力」で分割単位を全体にし、FLACまたはWAVで出力して4行が台本順に1本になることを確認。欠落、重複、極端な音量差がないか聞きます。
5. 録音も処理も停止した状態でアプリを閉じ、同じプロジェクトを「開く」。採用テイク・メモ・時間設定が残ることを確認します。再出力した結合音声も確認してください。
6. 任意：録音中に「取り消し」を押し、その録音がテイクとして残らないことを確認します。録音していないときは「取り消し」と「停止して保存」が無効であることも確認します。

各発話の「この発話の読み上げテスト手順」に確認点があります。01の結果だけでも結果記入用.mdの「録音」に記入して返せます。

## 2. 人間音声を正解にして読み補正を評価する

別の新規プロジェクトに02-reading.txtを取り込みます。01と同じ画面操作で4発話を録音・採用します。下の意図する読みで読みますが、期待値を音声確認なしに正解へ写さないでください。読み間違えたら録り直します。橋／箸などのアクセントはご自身の普段の読みで構いません。地域差も所見に残せます。

| 行 | 意図する読み | 確認点 |
|---|---|---|
| 1 | はしをわたってから、はしをおいてください。 | 橋と箸のアクセント。かな一致だけでは判定不可 |
| 2 | いちばでかいものをしたあと、かぶしきしじょうのどうこうをしらべます。 | 市場の出現位置別の読み |
| 3 | にんきのみせですが、へいてんごはひとけがありません。 | 人気の出現位置別の読み |
| 4 | しめきりはくがつさんじゅうにちなのに、しりょうがみつかりません。 | 日付と自然な間 |

1. 「読み確認・補正」で採用音声を試聴し、正解読みを入力。任意で「ローカル認識」→「読みの下書きへ」を利用し、誤認識があれば修正します。言い間違いを期待読みで隠さず、必要なら録り直してください。
2. 原文欄で対象語を選択し「正しい読み」に入力して「原文と正解読みの対応を登録」。2行目は先頭の市場=いちばと後半の市場=しじょう、3行目は前=にんきと後=ひとけを別々に登録。その後、正解読みを確定。
3. TextToSpeech CLI側の接続設定を準備し、「比較・採点」→「AI提案なし・標準の声で比較」を実行。既存のTextToSpeech CLIと保存済み接続設定を使います。録音のみのテストではこの準備は不要です。
4. 最初の比較は誤読を調べる予備試験です。候補を試聴し、候補名を開示して原文Aの実際の誤読を記録。「聴こえた読み」は聞いた通りに保存し、ASR結果の誤りと合成音声の誤りを分けます。
5. 誤読があった語だけ「読み確認・補正」で該当位置を選択し、補正候補を追加→採用。誤読がなければ補正ゼロで正常です。市場だから必ず補正する、といった操作は不要です。
6. 新しい比較を生成。今回は候補名を開示する前に音声1～3を各軸1～5で採点して保存。分からない項目は未採点。最後に開示してA/B/Cの結果を記録します。以前の比較との混同を防ぐためrun IDも控えます。
7. アプリを再起動して同プロジェクトを開き、読み・補正・採点の保存を確認。結果記入用.mdへ確認結果を記録してください。

02の人気は、この台本では後半を「ひとけ」と読む意図です。文章単独では解釈の幅があるため、他の文脈にも常に適用できるルールとは判断しません。読み改善がなかった場合も、そのまま記録してください。

## 3. 追加確認と未使用文

03-additional.txtは基本試験の後に任意で試す4文です。読みの目安は順に「りょうりのしたごしらえがおわったら、ひをよわめてください。」「このものがたりのしゅじんこうは、たびさきでふるいてがみをみつけました。」「ごごさんじにしゅうごうし、ごふんごにしゅっぱつします。」「どうもありがとう。ほんとうにたすかりました。」です。実際の発話を確認して正解を決めます。

04-validation-later.txtはルール候補を作るまでプロジェクトへ取り込まないでください。ルール機能は候補作成時点で既に使用済みの原稿を検証から除外します。候補作成後に必要な文だけ追加し、同じ話者・版・辞書条件で録音と比較を実施。読みは市場=いちば、金融市場=きんゆうしじょう、公園の人気=ひとけ、作家の人気=にんきです。候補と同じ語・読みの文を使い、改善しない結果も登録します。この4文は探索的な再確認用で、文脈も近いため一般化を証明する最終評価セットではありません。

## 結果の返し方

結果記入用.mdをコピーして記入し、まず録音の成否と気になった発話を教えてください。全項目を一度に埋める必要はありません。品質の優劣を事前に決めず、未実施・判断不能もそのまま記録します。

不具合は「操作直前の状態→押したボタン→実際の結果→期待した結果」、発話番号、エラー文を記録。プロジェクトの場所とレポートの場所も控えてください。音声や認証ファイルを提出する必要はありません。

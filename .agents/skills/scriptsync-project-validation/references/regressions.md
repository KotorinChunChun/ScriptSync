# UI・音声・保存の回帰確認

変更に関係する項目を選ぶ。キーの割当・有効条件は [キー定義](../../../../dev/SHORTCUT_KEYS.md)、効果音は [効果音定義](../../../../dev/SOUND_EFFECTS.md) を正本とし、ここに数値やキー表を複製しない。

## 非同期処理と画面

- 録音開始→停止保存→試聴→採用→次の発話を繰り返し、最後の採用まで操作可能であることを確認する。通常・連続モードの違いをキー定義に従って確認する。
- Promiseを保留できるUI試験で処理中を観察し、二重実行防止、成功・失敗・取消後の解除を確認する。処理が即終了するモックだけでロック不具合を検証しない。
- 保存済みテイクが取消操作で消えないこと、未保存トリム中の採用制限、再生終了・停止時のトグル復帰を確認する。
- リロード抑止と、実際に再接続が起きた場合の録音停止・保存完了・操作復旧を別々に確認する。連続録音やグローバルキー監視を勝手に復帰させない。
- 先頭・末尾でナビゲーションが巡回しないこと、無効な台本行が録音対象から除外されることを確認する。
- レイアウト変更はフルHDおよび対応する小さい画面で、documentのscrollHeight/clientHeightと幅を確認し、スクリーンショットも見る。テイク・原稿の領域内スクロール、固定操作部、選択色、文字サイズを確認する。全体をoverflow:hiddenにして操作が欠けていないかも見る。

## テイクと保存

[保存契約](../../../../docs/architecture.md) を参照する。

- 開始終了の数値とドラッグ位置が同期し、試聴が終了位置で停止することを確認する。
- トリム保存では実音声のサンプル数・長さ・ハッシュ・波形を確認し、編集範囲が新音声の両端に戻ることを確認する。
- メタデータ追加は旧保存データを読めることを確認する。評価だけの変更でメモ等が失われないことを、保存して再度開く試験で検証する。
- revisionsを正本として確認し、索引だけの書換えで保存成功としない。

## 結合・キャッシュ・外部連携

[連携仕様](../../../../docs/EXPORT_BLOCK_MAP.md) を参照する。

- 選択ブロックの試聴では、そのブロックだけを生成・再生する。他ブロックの欠損に影響されないことを確認する。
- 全体試聴キャッシュは同条件で再利用し、音声・設定変更時に古い結果を使わないことを確認する。欠損・破損キャッシュの再生成と、入力音声の整合性エラーを区別する。
- 音声、VTT、JSONが共通の配置フレームに基づくことを、実音声の長さ、字幕区間、ブロック累積時刻で照合する。秒数の丸めと、挿入無音・テイク区間・実際の発声開始の違いを区別する。
- 自動名と編集名の両方で禁止文字・長さ・空名を検証する。番号・拡張子・音声と字幕の対応は仕様書に従う。
- 出力先パスは実際に生成された場所と照合する。Explorerで開くことはファイル生成とは別に確認する。

## 録音下書き・AI改善・辞書

- 台本確定とディスク保存を区別する。保存済み未確定下書きは再起動後に復元し、再反映で競合や二重適用にならないことを確認する（recordingFeedback/projectClose/sourceManagement試験）。
- AI結果は承認前に修正案へ書かない。取消は元文を保持し、入力・選択・プロジェクト変更後の古い結果は反映しない（v005Workflow試験）。
- 辞書は端末設定として保存する。長い一致優先、一回置換、英数字境界、旧設定の空辞書互換、custom prompt保持を確認する（settingsView、machine_settings、text_improvement試験）。
- 選択行追従は同じ選択の再描画で手動スクロールを奪わず、閉じた祖先を開く（navigationFollow試験）。中央位置・操作ボタン重なりは実画面で確認する。

# ScriptSyncWebとの台本・録音ZIP交換（v0.0.5）

ScriptSyncで確定した台本をWebへ渡し、Webで修正・録音した内容をデスクトップの台本と録音候補へ取り込む手順です。ネイティブのプロジェクト保存形式とは別の交換形式を使用します。

Webの入口：[ScriptSyncWeb](https://dev-k.sakura.ne.jp/tools/scriptsyncweb/)。設定画面からも開けます。

## 台本をWeb用ZIPへ出力する

1. プロジェクトを開き、台本画面で出力する原稿を選択します。
2. 編集内容を渡したい場合は、差分と読み上げ対象を確認して「台本確定」を実行します。
3. 台本確定の右にある「ウェブ版用にエクスポート」を押します。編集後は再確定が必要です。
4. 保存先と新しいZIPファイル名を選択します。
5. Web側のZIP取り込み操作で、そのファイルを読み込みます。

出力単位は選択原稿1件です。分割前原稿には最後に確定した本文を入れ、Webの録音行にはその原稿の有効な発話を指定順で入れます。対象外の発話、空の録音行、既存のテイク音声は出力しません。未確定の本文はZIPへ反映しません。

ZIP内の原稿名は、選択原稿の名前から使用できない文字を置き換えた `.md` 名になります。同じ名前のZIPへの上書きは現在拒否するため、新しい名前を指定してください。出力操作自体は台本確定の代わりになりません。

## Webから修正台本と録音を取り込む

1. Web側で台本を修正・録音し、交換ZIPを書き出します。
2. デスクトップの台本画面で、取り込み先の原稿を選択して「WebZip取り込み」を押します。
3. 暗号化ZIPの場合はキーを入力します。非暗号化ZIPの場合は空欄のまま「ZIPを選択」を押します。
4. ZIPを選択します。検査に成功すると、原稿本文が台本編集の下書きへ渡されます。
5. 既存の差分確認で変更を確認・承認し、読み上げ対象や行対応を調整して「台本確定」を押します。
6. 「録音を追加する発話を確認」で、Webの各録音行と取り込み先発話の対応を確認します。
7. 「候補へ追加」を押します。追加件数と重複除外件数が表示されます。

対応画面にはWebの本文、行番号、テイク数、Web採用情報の有無を表示します。本文が一意に一致する場合は対応先を候補として選択しますが、最終確定は利用者が行います。同じ本文が繰り返される行、分割・結合した行、不一致の行は対応先を手動で指定してください。ZIPのファイル名やWebのテイクIDを台本照合キーにはしません。

音声を持つすべての行に対応先が必要です。対応先のない音声を黙って破棄しません。複数のWeb行を同じデスクトップ発話へまとめる対応は現在受け付けません。

「後で追加」を押すと音声追加を保留できます。同じプロジェクトを開いている間は「取込音声を追加」から再開します。取り込み待ちZIPはメモリ上の一時情報で、プロジェクトを閉じた後の復元対象ではありません。閉じた場合は元のZIPを選び直してください。

台本確定と録音追加は別の処理です。台本確定後に音声追加を取り消した場合も、確定した台本は残ります。台本編集が未確定の間は音声追加を実行しません。

## 既存録音と重複の扱い

- 取り込んだ録音は対応発話の候補へ追加します。既存テイクや現在の採用状態を置き換えません。
- Webで採用済みでも、デスクトップでは自動採用しません。Webの採用情報は確認用です。
- 重複判定は、同じ取り込み先発話にあるWAVファイル全体のSHA-256一致です。WebのIDが違ってもハッシュが同じなら追加しません。
- Webで同じテイクを編集し、同じIDでも音声ハッシュが変わっている場合は別候補として追加します。
- 別の発話で使用する同じ音声まで一括して除外することはありません。音が似ているという理由だけでは重複扱いにしません。
- Webの「採用のみ」のZIPは既存の不採用テイクを削除する指示ではありません。

録音追加の保存に失敗した場合は、追加前のプロジェクト状態へ戻し、その操作で作成した音声・付属ファイルを取り除きます。既存の音声や採用を変更しません。台本確定まで巻き戻す処理ではありません。

## 暗号化ZIPと編集前音声

Webの端末保存ZIPは非暗号化、サーバー保存ZIPはAES-256とキーを使用します。デスクトップは両方を読み込みます。サーバー保存で発行された6桁キーは、取り込み画面の暗号化キー欄へ入力します。キー違い・不足・破損などで検査できない場合は、台本と録音を取り込みません。

Webの `original` は編集前音声の付属データです。取り込み後は同じテイクフォルダーの `original.wav` として保持し、独立した録音候補を増やしません。WebのID・作成日時・採用情報などは `web-exchange.json` に保持します。デスクトップの候補一覧では取り込み時刻を使用します。

この版では、付属する編集前音声へ戻す専用ボタンはありません。通常の「DL」は現在のテイク音声を書き出します。編集前音声の再利用にも備える場合は、受け取った交換ZIPも保管してください。同じ音声を重複として除外した場合は、そのZIPの付属情報を既存テイクへ追記しません。

## 形式と検査上限

対応形式は `scriptsyncweb-exchange-1` です。ZIP内の `project.json` が正本で、`scripts/<原稿名>.md` と番号付き `script.txt` を併せて出力します。旧交換ZIPの原稿ファイル名省略は受け付けます。旧 `voice-notebook-1` はこのデスクトップ取り込みの対象外です。

| 項目 | 上限・条件 |
|---|---|
| ZIPファイル | 100MiB |
| 展開合計 | 120MiB |
| 音声合計（編集前音声を含む） | 100MiB |
| project.json | 4MiB |
| ZIP項目数 | 5000 |
| 交換行数 | 1～1000 |
| 作品名 | UTF-16コード単位で100以内 |
| 1行の本文 | UTF-16コード単位で20000以内 |
| 原稿ファイル名 | UTF-16コード単位で255以内 |
| 1行のテイク数 | 200 |
| 音声 | PCM16、48kHz、モノラルまたはステレオのWAV |

パス逸脱、重複項目、シンボリックリンク、音声ファイル不足、SHA-256不一致、WAVの実形式・長さと記載情報の不一致を拒否します。ZIPは検査中に利用者指定のパスへ展開せず、検査済み音声だけを新しいテイクフォルダーへ保存します。

文字数はWebのJavaScriptと同じ数え方です。多くの絵文字は2文字分として数えます。出力対象が0行の場合や上限超過の場合は、ZIPを作成する前にエラーを表示します。

Webの行番号は空行除外・句点分割後の順序で、デスクトップ原稿の物理行番号とは一致しないことがあります。読み上げ対象と原文の行順が異なる場合も含め、録音対応表で確認してください。

## 検証範囲

合成fixtureによる試験で、確定本文・指定順のZIP往復、パス逸脱・改ざん拒否、重複除外と採用保持、保存競合時の巻き戻し、AES-256の正誤キー、編集前音声の付属保持を確認しています。これらは自動試験であり、実際のWeb・スマートフォン・利用者の録音を用いた往復確認を代替しません。

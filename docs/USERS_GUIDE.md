# 利用者ガイド

## 起動と保存

`npm run tauri dev` で起動します。新規プロジェクトでは親フォルダを選び、その下に専用フォルダを作ります。「開く」では作成済みのScriptSyncフォルダを選びます。操作を保存すると履歴が `revisions/` に残ります。バックアップは作業フォルダ全体をコピーしてください。同じフォルダを複数のアプリで同時編集することはできません。

## 台本を録音して結合する

1. 左の「台本を追加」に貼り付けるか、TXT/Markdownを取り込みます。空行を除く1行が1発話になります。
2. 発話を選び、マイクを指定して「録音開始」。停止すると別テイクとして保存されます。1回最大5分です。
3. 試聴して「採用」を押します。取り直しても旧テイクは残ります。WAVファイルの取込も可能です（mono/stereo、8～192 kHz、1ファイル128 MB以内）。
4. 「結合・出力」で発話ごとの前後トリムと追加する間を秒単位で指定します。既定は原音全体、追加無音0秒です。原音は加工しません。
5. 「完成WAVを作成」で、採用音声を台本順に結合します。未採用・破損・差替えがある場合は止まります。不要な行は「結合対象外」にしてください。

出力は作業フォルダの `exports/<ID>/audio.wav`（48 kHz stereo PCM16）です。`manifest.json`に採用順と元音声hash、開始・終了フレームを保存します。出力後はアプリ内で試聴できます。4 GBを超えるWAVは台本を分けてください。音量超過がある場合は出力結果に件数を表示します。

録音のPeakや音量警告は録音品質の補助です。雑音・言い間違いは必ず試聴してください。マイク消失時に別の機器へ勝手に切り替えません。停止・失敗音声は保持され、前回中断したテイクは次回に「中断」と表示されます。回収可能なWAVは取込で検査できます。壊れたWAVの完全修復は保証しません。

## 読みあわせ・局所補正

1. 採用テイクを選び、「読み確認・補正」を開きます。
2. 正解音声を聴いてひらがなを入力します。「ローカル認識」は下書きと時刻候補を作成します。「読みの下書きへ」で反映し、必ず試聴・修正してから正解を確定します。
3. 原文欄の語を選択し、正しい読みを入力して「原文と正解読みの対応を登録」。位置は0始まり、終了は含まないUnicode文字単位です。同じ語も別位置として登録します。対応を変更したら正解を再確定します。
4. 「比較・採点」で3種類の音声を生成します。原文・全文かな・局所補正を共通の声条件で合成します。初回は補正ゼロでも実行できます。
5. 生成音声を試聴し、必要なら認識候補を使って「聴こえた読み」を保存します。「差分区間を表示」で読み差分と登録済みの原文対応候補を確認します。時刻ボタンはASRの推定区間を再生します。
6. 「読み確認・補正」で誤読箇所だけを補正候補に追加し、採用・却下・保留を選びます。重複範囲は採用できません。その後、新しい比較を生成します。

ASRは実際の音を漢字に復元するため、誤読を隠す場合があります。自動一致は発音・アクセントの正解を保証しません。位置が曖昧な候補は保留にしてください。全文かなと原文は合成CLIの各500文字以内に分割して登録します。

Codex提案では原稿をCodexへ送信します。音声認識はローカルです。雨衣の `release/amekoro-speech.exe` と `settings/voisona.dpapi` を利用するため、保存したWindowsユーザーで起動し、VoiSona TalkのAPIを有効にしてください。話者・Codexモデルは雨衣の既定／保存設定を利用します。

提案の検証エラーが出た場合は「AI提案なし・標準の声で比較」も使用できます。これはCodexで表現を提案せず標準値を使用する明示的な選択です。「同じ条件で再試行」は保存済みの声条件を使います。原稿・正解・補正が変わった場合は新しい比較にしてください。

## 比較採点と履歴

候補は匿名順で表示され、「候補名を開示」で名前が分かります。正確さ・自然さ・アクセント・抑揚と間・感情を1～5で保存します。1=強い違和感、3=違和感はあるが伝わる、5=自然。判断できない項目は未採点のままにします。

原稿変更後はテイクの採用と正解を再確認してください。以前の音声・採点は履歴に残り、条件が変わった比較には注意が表示されます。評価レポートはJSON/CSV/HTMLで出力できます。

## 品質確認

人間の音声による最終品質評価は別途行います。追加機能とTalk連携の検証範囲は以下を参照してください。

## 追加機能（2026-09-08）

### 収録とテイク整理

台本を拡大し、前後の発話を見ながら収録できます。開始前の待ち時間は0・3・5秒から選択。Ctrl+Rで録音、Escで停止またはカウントダウン取消、Spaceで試聴、Alt+左右でテイク切替、Ctrl+Enterで試聴テイクを採用して次へ進みます。未試聴の場合は最新の正常テイクを採用します。文字入力欄ではこれらの開始・採用ショートカットは働きません。

テイクごとにメモとお気に入りを保存できます。左の要確認フィルターは、未収録・未採用・読み未確定・補正保留・原稿変更後の再確認を表示します。「次の対象へ」は表示条件に合う次の発話へ移動します。

### 波形・音量とつなぎ目

「結合・出力」で採用音声の波形を表示し、ドラッグして残す区間を指定します。秒数入力でも調整できます。「時間設定を保存」で反映します。「現在のトリム・音量を試聴」は入力中の設定を使い、繰り返し再生も可能です。つなぎ目試聴では現在の発話の末尾1秒と、追加した間、次の発話の先頭1秒を再生します。試聴用WAVもexportsに履歴として残ります。

ゲインは-36～24 dBで任意指定します。調整案はRMS -20 dBFSを目安とし、ピークが-1 dBFS以下になるよう制限します。「音量設定を保存」で完成WAVに適用します。RMSはラウドネス規格値ではなく目安です。原音と読み比較用音声は変わりません。

### 台本の改訂

原稿欄のカーソル位置で保存済み発話を分割し、次の発話との結合もできます。旧発話は履歴へ残ります。録音は候補として引き継がれますが、分割した文字に合わせて音声を自動分割する機能ではありません。再採用し、必要なトリムまたは録り直しを行ってください。

「台本全体を改訂・履歴を確認」に新台本を貼り付け、差分を確認してから適用します。同じ位置で原稿が一致する行は保持し、それ以外は再確認対象にします。削除・変更前の発話は履歴から末尾へ復元できます。差分確認後にプロジェクトが更新された場合は再確認が必要です。

### 一括処理と比較

左の「複数発話を一括処理」で発話とASR／合成を選びます。合成は標準の声が既定。AI提案なしのチェックを外すと原稿をCodexへ送ります。成功・失敗・中断は発話ごとに保存され、失敗・中断分だけ再試行できます。生成音声の個別採用や正解読みの確定は自動で行いません。

比較画面の「該当箇所を並べて比較試聴」では、人間音声と最新比較の各音声に個別の開始・終了秒を指定し、同じ語の前後を試聴できます。区間設定は現在の画面セッション中に保持します。

### 補正事例・読点・ルール

読み確認画面で他の発話の承認済み補正事例を検索できます。文脈を確認し、現在の原文の同じ語を選択して保留候補として追加します。

読点比較では、生成済みの局所補正を基準に「、」だけを追加・削除・移動します。他の文字の変更は拒否します。かな補正と実話者条件を固定した2候補を生成し、従来と同じ匿名試聴・採点を行います。

ルール候補は、補正1件だけの比較で、読みの正確さが改善し、自然さが維持され、補正後の両評価が4以上のものから作成します。辞書条件はAPIから取得できないため利用者が確認して記録します。候補作成時に使用済みの原稿は検証に使えません。新しい文で同じ語・読み・声・辞書条件の比較を行い、検証結果を登録します。反例も保持され、改善しない検証がある場合は承認できません。承認済みだけを根拠JSON付きのプロンプト用Markdownへ出力します。雨衣側の設定は書き換えません。

Talk編集ファイルは田中さん・ハスキー0で試験対応。各生成音声からtstprjを出力し、Talkで保存したファイルの再読込もできます。**Talk実画面の読込・編集・保存・再合成は未検証**です。[形式と検証範囲](talk-project-format.md)を参照してください。

### 保存互換性

製品バージョンはv0.0.1のまま、追加情報の保存形式を2へ更新します。旧形式1は新アプリで読めます。旧アプリが追加情報を落として保存することを防ぐため、形式2は旧EXEからは開けません。以後の作業は新しいビルドを使用してください。

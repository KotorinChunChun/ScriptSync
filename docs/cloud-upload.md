# Web・会社クラウドへの台本送信

対象：v0.0.4。最終更新：2026-09-12。

台本画面から、最後に確定した選択原稿をScriptSyncWeb互換のZIPとして送信できます。台本確定と送信は別操作です。未確定の編集内容と既存テイクの音声は送信ZIPに含めません。修正台本・録音の返却は「Web ZIP取込」を使います。

## 共通の操作

1. 台本画面で送信する原稿を選択し、必要な編集・差分承認・読み上げ対象設定を行って「台本確定」を押します。
2. 画面下部の送信先から「Web」「ZIP出力」「会社OneDrive」「Box」を選びます。
3. 隣の「台本を…」ボタンを押します。「ZIP出力」はローカルの保存先を選び、それ以外は送信画面へ進みます。
4. WebはHNとキー、会社クラウドはユーザー認証を用意します。
5. 「台本ZIPを送信」を押し、送信確認を承認します。完了メッセージを確認します。

認証できただけでは原稿を送信しません。送信確認を取り消すと送信しません。設定を変更する場合は「設定」→「会社のクラウド連携」で値を入力し、「設定を保存」を押します。「クラウド連携の導入案内」から登録手順と認証解除を確認できます。

## ScriptSyncWeb

接続先：[ScriptSyncWeb](https://dev-k.sakura.ne.jp/tools/scriptsyncweb/)。設定画面のURL・起動ボタン・QRコードから開けます。QRコードはWebの起動用であり、原稿やワンタイムキーは含みません。

1. 送信先「Web」を選びます。
2. 送信画面でHNと数字6桁のワンタイムキーを入力します。既に使用中のHNを使う場合は、そのHNに対応するキーを使用します。
3. 「台本ZIPを送信」を押して確認します。
4. 保存完了後、スマートフォンでWebを開き、同じHNとキーを入力してサーバーのZIP一覧から取得・取り込みます。

ZIPはAES-256で暗号化して送信します。Webの既存認証方式に合わせ、HNを含むsaltと150,000回のPBKDF2-SHA256で認証トークンを生成します。512KiBずつ送信し、サーバーの完了応答を確認してから成功表示します。転送失敗時は今回作成した転送予約の削除を試みます。接続断により削除できなかった場合は、Web側の期限切れ回収の対象になります。

Webサーバーの保存期間は24時間、ZIP上限は100MiBです。HN・キーはアプリの設定ファイルに保存しません。キーを忘れた場合にアプリから復元する機能はありません。Web側の空き容量・HNごとの保存数・認証回数制限によって送信が拒否される場合があります。

## 会社のOneDrive

### 管理者・登録担当者の準備

1. 会社のMicrosoft Entraテナントにアプリを登録します。
2. Microsoft Graphの**委任されたアクセス許可** `Files.ReadWrite` を設定します。会社の方針に応じた同意・承認を行います。
3. アプリ登録でパブリッククライアントフローを有効にします。本実装はデバイスコードフローを使用し、Entraのclient secretは使用しません。
4. 利用者のOneDrive内に送信先フォルダーを作成します。アプリはフォルダーを自動作成しません。
5. アプリの設定画面へ次の値を入力して保存します。

| 設定 | 入力例・意味 |
| --- | --- |
| Entra テナントID | 会社のディレクトリーのGUID。初期値は既存の指定値 `a0fa18d4-3880-44a4-b5b2-bf59e18d7fc2` |
| Entra アプリのクライアントID | 登録したアプリのGUID。テナントIDとは別の値 |
| OneDrive 保存先フォルダー | ドライブ直下からの既存パス。例：`ScriptSync`、`制作/台本`。空欄ならルート |

会社の条件付きアクセスでデバイスコードフローが禁止されている場合は利用できません。アプリ側で会社のポリシーを変更・回避する機能はありません。

### 利用者の認証と送信

1. 送信先「会社OneDrive」を選びます。
2. 「ユーザー認証を開始」を押します。
3. 表示されたコードをMicrosoftの認証画面へ入力し、会社のアカウントでログインして同意します。ブラウザーを閉じた場合は「認証画面を開く」で開き直せます。
4. ScriptSyncへ戻り、「認証できました」の表示を確認します。
5. 「台本ZIPを送信」を押して確認します。

認証した利用者のOneDriveへ送ります。SharePointライブラリーや任意の別利用者のドライブ指定には対応していません。送信ファイル名は `ScriptSync-<一意のID>.zip` です。毎回異なる名前で保存し、既存ファイルの更新には使いません。クラウドへ送るZIP自体は非暗号化で、HTTPSと送信先サービスのアクセス制御を使用します。

## Box

### 管理者・登録担当者の準備

1. Box開発者コンソールでStandard OAuth 2.0を使用するアプリを登録します。必要なファイル操作権限と、会社で必要な承認を設定します。
2. リダイレクトURIへ **`http://127.0.0.1:8767/callback`** を正確に登録します。
3. 設定画面の「Box クライアントID」にアプリのID、「Box 保存先フォルダーID」に送信先IDを入力して保存します。ルートは `0` です。
4. 認証時に使用するclient secretを、登録担当者から利用者へ会社の運用に沿って用意します。アプリ本体やリポジトリーへsecretを埋め込まないでください。

Boxは会社のEntra認証とは別のAPI認可です。Boxのログインで会社のSSOを使用する場合も、Boxアプリへの利用許可が必要です。

### 利用者の認証と送信

1. 送信先「Box」を選びます。
2. 送信画面の「Box client secret」に今回使用するsecretを入力します。
3. 「ユーザー認証を開始」を押し、ブラウザーでBoxへログインして許可します。
4. ブラウザーにScriptSyncへ戻る案内が出たらアプリへ戻り、認証完了を確認します。
5. 「台本ZIPを送信」を押して確認します。

認証コールバックの受信には、このPCの `127.0.0.1:8767` を使用します。別のアプリが同じポートを使用中の場合は認証を開始できません。認証要求とコールバックのstateが一致しない場合は認証を確定しません。

client secretは認証の間だけメモリーへ保持し、設定ファイルやプロジェクトへ保存しません。アプリ配布物に共通のsecretを同梱する構成にはしていません。トークン交換後はsecretの保持を終了します。端末専用の永続資格情報保管庫には未対応です。

送信先には認証した利用者が操作できるフォルダーを指定してください。ファイル名は `ScriptSync-<一意のID>.zip`、ZIPは非暗号化です。Boxの保存容量・権限・会社ポリシーによって送信が拒否される場合があります。

## 認証状態・失敗時の扱い

- OneDriveとBoxのアクセストークンはアプリのメモリーにだけ保持します。アプリ終了後や有効期限切れ後は再認証します。バックグラウンドでのrefresh token更新は行いません。
- 「設定」→「クラウド連携の導入案内」→「クラウドの認証を解除」で、このアプリが保持している認証を解除できます。サービス側のブラウザーログインや同意登録を削除する操作ではありません。
- 認証待ちの送信画面を閉じると、アプリ側の認証待ちを解除します。
- ネットワーク切断・権限不足・登録不備・保存先不明は失敗表示します。エラーが出た場合は送信先側の一覧も確認し、不要な重複送信を避けてください。接続が切れた時点によってはサーバーに保存済みでも完了応答を受け取れないことがあります。
- 設定のIDやフォルダーはPCごとに保存され、プロジェクトには持ち回りません。

## 検証範囲

実装時にUIのRPCモックで入力不足・確認取消・認証未設定・送信失敗・認証開始と画面終了の競合を検証しました。Rust試験ではWeb転送手順、暗号化ZIPの復号、失敗時の予約削除、Boxのstate検証、未登録時の失敗を確認しています。これらは実サービスへの認証・送信成功を証明するものではありません。

2026-09-12の本書作成時点では、会社OneDrive／Boxの登録情報を用いた実認証・実アップロード、および公開Webへの実送信は未検証です。最新の統合試験結果は [v0.0.4実装記録](../dev/v0.0.4-imp.md) を参照してください。

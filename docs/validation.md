# 実証・受け入れ方針

## この文書を読むとき

次の場面では、試験を始める前に本書を読みます。

- 実装変更に必要な自動試験・実機試験・受入確認を選ぶとき
- 録音品質、読み認識、音声合成、比較採点の結果を評価するとき
- 保存、旧形式移行、外部CLI、Web交換、配布物を検証するとき
- 自動試験の成功だけで完了と判断できるかレビューするとき
- 利用者へ確認を依頼し、条件と結果を再現可能に記録するとき

本書には、今後のバージョンでも使う検証原則、条件、評価方法だけを置きます。特定バージョンで実行した試験件数、日付、成果物、未確認事項は、対象版の `dev/vX.Y.Z-imp.md` または `dev/history/vX.Y.Z/` が正本です。本書へ版別の結果を追記しません。

変更ファイルから具体的なコマンドを選ぶときは、[開発者ガイド](DEVELOPERS_GUIDE.md)と[ScriptSync変更検証スキル](../.agents/skills/scriptsync-project-validation/SKILL.md)も参照します。

## 検証の原則

- 自動試験、ブラウザーのRPCモック、ネイティブアプリ、実マイク、外部サービスを別の証拠として扱う。
- 過去に成功した件数を、今回実行した結果として転載しない。
- 実施日、対象コミット、入力、端末・デバイス、外部ソフトの版、成功条件を結果と一緒に記録する。
- ignored、未実施、環境による中断、機能不具合を区別する。
- 原稿、録音、認証情報などの利用者データを無断でfixtureへ流用しない。
- 保存失敗や破損の試験で、既存プロジェクトや正常音声を上書きしない。
- AIやASRが生成した内容を、結果を見てから正解データへ採用しない。

## 変更領域と最低限の検証

| 変更領域 | 最低限の検証 |
|---|---|
| 文書・スキル | 相対リンク、現行仕様との一致、frontmatter、`git diff --check` |
| UI・CSS・キー | 関連UI試験、UI全体試験、本番ビルド。配置変更は対象解像度の実ブラウザー確認 |
| 保存・原稿・移行 | Rustの関連試験と全体試験。旧形式、再読込、保存失敗、競合、世代保持 |
| 録音・音声加工 | 録音crateと呼出側の試験。実マイク変更は同一条件の録音と聴感確認 |
| 再生・デバイス | endpoint伝達試験と、指定機器から聞こえる実機確認を分ける |
| Whisper・Codex・外部CLI | モック契約に加え、許可された非機密入力による実環境試験。認証と入力送信範囲を記録 |
| ZIP・Web送信 | ローカル契約、暗号化、失敗復旧、サイズ制限。実送信した場合だけ公開先の取得結果を記録 |
| 配布・起動 | Releaseビルド、署名、成果物hash、インストール、正式入口からの起動を必要範囲で個別確認 |

コードを変更していない文書整理では、製品ビルドを自動では実行しません。逆に、画面・録音・保存・出力を変更した作業を文書検査だけで完了にはしません。

## 読み上げテストの入口

[読み上げテスト](../samples/reading-test/README.md)には、録音、読み分け、追加文、未使用文、結果記入用の入口があります。人間音声、マイク、連続操作、聴感を確認する場合は、試験対象に合う文章だけを選び、同じ条件で比較します。

録音品質の比較では、少なくとも次を揃えます。

- 同一PC、同一入力endpoint、同一形式、同程度の発話時間
- ScriptSyncと比較対象アプリの開始・停止条件
- Windowsの音声拡張、リモート接続、入力ゲインの状態
- 保存音声長、欠落・不連続診断、聴取環境
- 再現回数と、問題が発生した録音・発生しなかった録音の両方

## 読み確認・補正の仮説

読み確認と補正を評価するときは、次を独立して判定します。

- 人間が確認した読みを基準にした局所補正が、原文の誤読を減らすか。
- 局所補正が、全文かな化より自然さを保てるか。
- 認識結果と確認画面が、人間の確認・補正作業を減らすか。

一つの成立だけで他も成立したと判断しません。人間が読んだ声の抑揚を合成音声が再現することは、文字上の読み一致とは別の評価です。

## 条件を揃える比較

| 候補 | 入力 | 目的 |
|---|---|---|
| A | 漢字原文 | 無補正の基準 |
| B | 人間が確認した全文かな表記 | 全文かな化の影響 |
| C | Aの実音声で確認した誤読箇所だけを補正 | 局所補正の効果 |
| D（任意） | AIや辞書による補正候補 | 人間確認に対する支援効果 |

話者、外部ソフトとモデルの版、辞書、声パラメーター、文分割、出力方式を固定します。条件が一致しない結果は別集計とし、除外理由を記録します。開発に使った文章と最終評価用の未使用文を分け、結果を見て期待値を作り直しません。

## 継続して使う確認文

| ID | 原文 | 確認点 |
|---|---|---|
| bridge | 橋を渡ってから、箸を置いてください。 | 同じかなでもアクセントは別評価 |
| market | 市場で買い物をした後、株式市場の動向を調べます。 | いちば／しじょうを位置別に扱う |
| popularity | 人気の店ですが、閉店後は人気がありません。 | にんき／ひとけを一括置換しない |
| deadline | 締切は九月三十日なのに、資料が見つかりません。 | 数字・日付・読点候補を分ける |

追加時は、数字、助数詞、略語、固有名詞、反復語、長文、感情の違い、補正不要な対照文を偏りなく含めます。補正箇所がゼロでも正常な結果です。

## 評価方法

読みは、置換・脱落・挿入を人間が聴取して記録し、誤読語数と誤読を含む文数を示します。かなCERは補助値とし、ASR自体の誤りと合成音声の誤読を分けます。分母がゼロなら算出不能とします。

自然さは、アクセント、語のつながり・抑揚、間、感情適合を別軸で評価します。提示順を固定せず、可能なら表記を伏せます。単一評価者の結果は探索的な個人評価として扱い、一般的な優位性を断定しません。

作業時間は、録音、正解確認、差分確認、補正、再試聴に分けます。処理待ち時間と人間の操作時間も分離します。

## 成功判定

| 判定 | 基準 |
|---|---|
| 機能受け入れ | 入出力追跡、原文保持、位置別補正、保存再開、有効音声、失敗表示、採点復元が対象範囲で通る |
| 読みの改善 | 基準で確認した誤読が補正後に直り、対象文へ新しい誤読を増やさない |
| 自然さの維持 | 読みの改善とは別に、各評価軸の悪化箇所と件数を示す |
| 録音品質 | 欠落・不連続・時間差の診断と、同一条件での聴感確認が一致する |
| 保存・移行 | 正常データを保持し、失敗を成功扱いせず、再読込後も意味が変わらない |
| 外部連携 | 入出力形式、版、認証範囲、失敗復旧、実行先を記録して再現できる |

## 自動・境界・障害試験

- 位置補正：原文一致、重複、逆順、範囲外、結合文字、反復語、挿入・脱落、ゼロ補正、本文版変更、長文。
- 認識・AI：無音、切れた録音、タイムアウト、空結果、古い結果、入力変更、取消、承認前の原文保持、辞書の境界。
- 合成・外部CLI：未起動、認証不可、非ゼロ終了、WAV欠落・破損、版不一致、空白・日本語パス、キャンセルと再開。
- 保存：終了・再起動、保存待ち、保存失敗、旧形式、破損世代、音声差替え、部分成功、競合、完全消去の再試行。
- UI：キーボード、初期フォーカス、狭い画面、スクロール、重なり、非同期中の操作、エラー解除。
- 出力・交換：無効行、未採用、トリム、間隔、分割、字幕なし、hash不一致、上限超過、中断、再送。

## 結果の記録先

実行したコマンド、成功・失敗・ignored、実機条件、証拠ファイル、未実施事項は対象版のIMPへ日本語で記録します。長い継続調査は `dev/testing/` を使い、解決後は該当版のIMPまたはその補足資料へ移します。本書は結果台帳にせず、検証基準が今後も変わる場合だけ更新します。

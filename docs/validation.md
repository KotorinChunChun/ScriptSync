# 実証・受け入れ計画

## 2026-09-08の実施結果とユーザー指定

ユーザー指定により、今回の自立試験はTalkへ正しいかな／意図的に異なるかなを渡した合成音声を使用した。人間音声と実マイクの確認は引き渡し後に実施する。Talk編集出力は調査を含めて今回見送り。以下の品質仮説・人間試験計画は将来の確認として保持し、今回の自動試験成功で置き換えない。

Rust通常11件、録音crate18件、UI4件、明示実行した実機2件が成功。必須4文章×A/B/Cの12音声生成が成功。ASRは4合成音声中3件で指定かなと一致し、1件は誤認識したため手動確認必須の支援機能とした。機能試験の詳細・証跡は `dev/v0.0.1-imp.md` に記録。

H1/H2/H3の最終判定、未使用文による品質、実マイクでの連続運用は未判定。実機で人間の音声を確認するための状態まで実装する。

## 検証する仮説

H1：人間の確認済み読みを基準にした局所補正Cは、原文Aの誤読を減らす。
H2：Cは全文ひらがなBより自然さを保ち、Aに対する自然さの悪化を抑えられる。
H3：実発話を保つ認識経路と確認画面により、手作業の確認・補正時間を抑えられる。

これらは仮説。H1成立だけでH2/H3を成立扱いしない。人間が読んだ声の抑揚を再現することは成功条件に含めない。

## 予備実証

同じ原稿に対して、人が意図的に「いちば／しじょう」「にんき／ひとけ」を読み分けた音声と正しい読みを用意する。正解ラベルは聴取して確定する。ASRに原文や正解読みを渡さず、不正読みが正しい読みへ復元される割合、差分見逃し、誤警報、手動修正時間を記録する。同じかなの橋／箸も入れ、文字照合だけではアクセントを識別できないことを確認する。

ASR候補の名称・版・デバイス・処理時間・出力粒度・費用条件・音声の送信先を記録して選定する。現時点では特定製品の対応可否を断定しない。認識精度不足なら手動確認率と制限を明示する。

## 条件を揃える比較

| 候補 | 入力 | 目的 |
|---|---|---|
| A | 漢字原文 | 無補正の基準 |
| B | 人間が確認した全文ひらがな（句読点は原文と対応） | 全文かな化の影響 |
| C | Aの実音声で確認した誤読箇所だけをひらがな化 | 新方式の効果 |
| D 任意 | 既存AIだけの選択補正 | 人間音声基準による追加効果 |

話者名・版、Talk/API版、辞書状態、声パラメーター、文分割、出力方式を固定する。条件不一致は比較対象から除外し、除外件数を報告する。Aを使ってCを作った開発結果と、確定したCを再合成した評価結果を分ける。再合成で誤読が再発する可能性も確認する。

初期案は下記4必須文でスモーク、その後新規文を含む12文程度で方式を調整する。最終評価用は未使用の別文群を事前に確保する。具体的件数と基準は予備実証後、最終評価前に固定する。同文の表記違い・近い言い換えは同一グループにまとめ、開発と評価に跨がせない。

## 必須ケース

| ID | 原文 | 確認点 |
|---|---|---|
| bridge | 橋を渡ってから、箸を置いてください。 | 読み一致でもアクセントは別評価。不要な仮名化を抑える |
| market | 市場で買い物をした後、株式市場の動向を調べます。 | 先頭いちば／後半しじょうを位置別に扱う |
| popularity | 人気の店ですが、閉店後は人気がありません。 | 前半にんき／後半ひとけ。文字列の全置換をしない |
| deadline | 締切は九月三十日なのに、資料が見つかりません。 | くがつさんじゅうにち。読点候補は別試験 |

追加カテゴリ：数字・助数詞・略語・固有名詞・同語反復・長い主題句・感情の異なる文章・読み誤りのない対照文。期待読みは人間の確定版であり、AIが結果を見て期待値を作り直さない。補正箇所ゼロも正常な結果。

## 評価方法

読み：人間が誤読箇所を聴取し、置換／脱落／挿入を記録。誤読語数／評価対象語数、誤読のある文数／評価済み文数を示す。かなCERは補助値とし、ASRそのものの誤りと合成誤読を別集計する。正解が空の場合など分母ゼロは算出不能とする。

自然さ：アクセント、語のつながり・抑揚、間、感情適合を別軸の1～5で評価する。1=強い違和感、3=意味は伝わるが違和感あり、5=自然、2/4=その中間。判断不能・未採点はnullで理由を残す。A/B/Cの提示順をseed付きで変え、表記を伏せて採点し、同等という対比較回答も保存する。

作業時間：録音、正解確認、差分確認、補正、再試聴を分けて計測。処理待ち時間と人間の作業時間を分ける。単一評価者なら個人の探索的結果として報告し、一般的な優位性を断定しない。

初期には同条件で各候補2回の生成を案として用い、生成ゆらぎを確認する。試聴用再生音量は統一し、元WAVへの加工は別記録にする。モデル間比較は利用可能な話者を追加した段階で別集計し、単一話者から一般化しない。

## 成功判定

| 判定 | 基準 |
|---|---|
| 機能受け入れ | 入出力追跡、原文保持、位置別補正、保存再開、全必須候補の有効WAV、失敗表示、採点復元が通る |
| 読みの改善 | Aで確認した誤読がCで修正され、必須例で新規誤読がない。Aに誤読がなければ改善は判定不能 |
| 自然さの維持 | A対C・B対Cの各軸を対比較。悪化箇所と件数を示し、読み改善だけで採用しない |
| 最終採用判断 | 予備試験後に自然さの許容差・必要評価数・作業時間目標を固定し、未使用文に適用する。それまでは探索的実証として報告 |
| Talk編集 | 読込・修正・保存・再読込・再合成の証跡と項目保持表。初期WAV経路とは独立判定 |

## 自動・境界・障害試験

位置補正：原文一致、重複・逆順・範囲外、絵文字と結合文字、反復語、挿入／脱落、ゼロ補正、原文版変更、かな展開後500文字超。

認識：無音、切れた録音、言い直し、ASRタイムアウト、かな以外の転記、時刻なし、原文に寄せた誤転記。曖昧な差分を自動採用しないこと。

合成：認証復号不可、Talk未起動、話者不明、CLI非ゼロ、WAV欠落／破損、実条件不一致、既存出力、空白・日本語パス、キャンセルと再開。接続設定ファイルの内容はログへ書かない。

保存とUI：終了・再起動、音声差替え、保存失敗、古いワーカー結果、採点null、部分成功、キーボード、録音停止、再生デバイス。PS1の再現入口を新リポジトリのscriptsへ作り、モック試験と実サービス試験を選択できるようにする。

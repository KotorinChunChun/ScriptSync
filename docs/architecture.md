# 現行アーキテクチャ

対象はv0.0.1です。初期構想は[初期設計案](history/architecture-initial-design.md)へ保存しています。v0.0.2の固定ID・複数Markdownマージは[次版計画](../dev/v0.0.2-imp.md)であり、以下の現行処理には含まれません。

## 処理の境界

TypeScript UIからTauriコマンドを通してRustへ操作を渡します。UIは5工程の表示と操作状態を管理し、Rustがプロジェクト保存・録音・音声加工・外部処理を担当します。ファイル単位の担当は[構成目録](REPOSITORY_MAP.md)を参照してください。

録音はローカルcrateを使用します。入力サンプルの取得、連続したリサンプリング、WAV書き込み、品質情報の集計を録音基盤側で扱い、アプリ側でテイクとして保存します。入力欠落の警告は失われた発話を復元できたという意味ではありません。

保存時に前後の無音を自動除去し、各0.1秒を残します。手動トリムは保存時に音声実体を作り直し、参照・ハッシュ・長さを更新します。波形・再生位置は保存後の音声時間を基準とします。

## プロジェクトと原稿

プロジェクトの入口は `.scriptsync` ファイル、データ本体は対応する `.scriptsync.data/` です。不変の `revisions/` 保存世代を正本とし、`project.json`は索引として扱います。破損した最新世代を黙って過去に戻して成功扱いにはしません。保存失敗時も既存音声・世代を保全します。

原稿の元テキスト、読み上げ用の編集テキスト、録音時の原稿を区別します。Markdownでは見出しを部・章・節、リストを項として扱い、行ごとの有効状態を保存します。無効な発話は録音対象から外し、音声を保持して再有効化に備えます。

v0.0.1のMarkdown対応付けは行と元テキストに依存します。大きな挿入・移動・複数ファイル更新を安全にマージする固定IDと対応編集画面はv0.0.2で実装予定です。

## 操作状態と録音の寿命

通常モードはアクティブ画面内のキー、連続録音は明示開始から終了までのグローバルキーを使用します。保存済みテイクと現在収録中のデータを分け、F1の取り消しで保存済み音声を消しません。キー仕様の正本は[キー定義](../dev/SHORTCUT_KEYS.md)です。

誤ったF5リロードを防止し、UIセッションの生存確認も行います。UI再接続・喪失時に収録が操作不能のまま続くことを防ぐ処理は `ui_session.rs` と `reloadProtection.ts` にあります。更新時の実録音保存は別途実機で検証します。

## 読み確認・比較と出力

認識は `tools/asr` のローカルPythonワーカー、合成は外部のTextToSpeech CLI経由です。TextToSpeech CLIは、テキストを渡して音声へ変換するCLIソフトウェアの抽象名であり、特定の製品・モデル・話者を指しません。表記はユーザー指定の「TextToSpeech CLI」に統一します。

認識結果・かな変換は候補であり、人間の確認なしに正解へ確定しません。位置別の読み補正、比較候補、採点とルールを別の記録として保持します。CLI側の音声合成エンジン形式は[形式資料](talk-project-format.md)を参照してください。文書中の実行パス、plan形式、TextToSpeech CLI連携は現行または当時の具体的な実装・検証条件です。すべてのTextToSpeech CLIが同じ引数や形式に対応することを意味しません。

録音の採用だけで結合出力へ進めます。読み確認・比較採点は必須ではありません。出力は採用音声を使い、分割境界・ファイル名・既定／ブロック別間隔・ノーマライズを適用してFLAC/WAVを生成します。プレビューは選択位置から再生し、停止操作を共通に扱います。

## 検証の範囲

UIはDOM・RPCモック、Rustは保存・境界・音声加工・出力などを試験します。外部サービス試験2件は明示実行が必要です。自動試験はネイティブキー、マイクの人声音質、OSダイアログの代替ではありません。[検証記録](validation.md)に実施条件と残る確認を分けて記載します。

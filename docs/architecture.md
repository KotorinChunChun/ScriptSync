# 現行アーキテクチャ

対象はv0.0.3です。初期構想は[初期設計案](history/architecture-initial-design.md)、今回の実装・検証状態は[実装記録](../dev/v0.0.3-imp.md)を参照してください。

## 処理の境界

TypeScript UIからTauriコマンドを通してRustへ操作を渡します。UIは5工程の表示と操作状態を管理し、Rustがプロジェクト保存・録音・音声加工・外部処理を担当します。ファイル単位の担当は[構成目録](REPOSITORY_MAP.md)を参照してください。

録音はローカルcrateを使用します。入力サンプルの取得、連続したリサンプリング、WAV書き込み、品質情報の集計を録音基盤側で扱い、アプリ側でテイクとして保存します。入力欠落の警告は失われた発話を復元できたという意味ではありません。

保存時に前後の無音を自動除去し、各0.1秒を残します。手動トリムは保存時に音声実体を作り直し、参照・ハッシュ・長さを更新します。波形・再生位置は保存後の音声時間を基準とします。

## プロジェクトと原稿

プロジェクトの入口は `.scriptsync` ファイル、データ本体は対応する `.scriptsync.data/` です。通常保存では不変の `revisions/` 保存世代を正本とし、`project.json`は索引として扱います。破損した最新世代を黙って過去に戻して成功扱いにはしません。保存失敗時も既存音声・世代を保全します。

原稿の元テキスト、読み上げ用の編集テキスト、録音時の原稿を区別します。Markdownでは見出しを部・章・節、リストを項として扱い、行ごとの有効状態を保存します。無効な発話は録音対象から外し、音声を保持して再有効化に備えます。

保存形式4で導入した順序付きscript_sourcesとSegment.source_idを、現行形式5でも保持します。ファイルごとのconfirmed_textは台本確定時だけ更新し、draft_textと行の選択・対応情報を別に保存します。録音等のgenerationと台本確定のscript_revisionは別です。同名再読込はファイル内で比較し、台本確定時にファイル順・読み上げ順へsegmentsを再構成します。読み上げ順の指定がない行は物理行順を使います。読み・採用・音声の参照は発話IDに付随します。旧形式は録音を保持した「既存台本」へ移行し、推測で元ファイルへ分割しません。

完全消去だけは例外として、明示確認したアーカイブ発話を保存世代から消去します。先にpendingジャーナルを保存し、全世代の参照を除いて専有音声・ASR成果物を削除、完了ジャーナルを保存します。共有参照のある音声は残し、中断時はpendingから再試行します。

## 操作状態と録音の寿命

通常モードはアクティブ画面内のキー、連続録音は明示開始から終了までのグローバルキーを使用します。保存済みテイクと現在収録中のデータを分け、F1の取り消しで保存済み音声を消しません。キー仕様の正本は[キー定義](../dev/SHORTCUT_KEYS.md)です。

誤ったF5リロードを防止し、UIセッションの生存確認も行います。UI再接続・喪失時に収録が操作不能のまま続くことを防ぐ処理は `ui_session.rs` と `reloadProtection.ts` にあります。更新時の実録音保存は別途実機で検証します。

## 読み確認・比較と出力

認識は `tools/asr` のローカルPythonワーカー、合成は外部のTextToSpeech CLI経由です。TextToSpeech CLIは、テキストを渡して音声へ変換するCLIソフトウェアの抽象名であり、特定の製品・モデル・話者を指しません。表記はユーザー指定の「TextToSpeech CLI」に統一します。

録音成功後の自動認識はautomatic_asr.rsの独立逐次キューを使用します。プロジェクト・発話・テイク・音声hash・本文revisionを固定し、録音を優先して認識を中断／再投入します。結果は元テイクへ保存し、本文版が一致する空の録音行だけを読み上げ本文と下書きへ補完します。プロジェクト切替や音声変更の結果は適用せず、開き直した際の中断状態は再実行可能な失敗として扱います。

認識結果・かな変換は候補であり、人間の確認なしに正解へ確定しません。位置別の読み補正、比較候補、採点とルールを別の記録として保持します。CLI側の音声合成エンジン形式は[形式資料](talk-project-format.md)を参照してください。文書中の実行パス、plan形式、TextToSpeech CLI連携は現行または当時の具体的な実装・検証条件です。すべてのTextToSpeech CLIが同じ引数や形式に対応することを意味しません。

録音の採用だけで結合出力へ進めます。読み確認・比較採点は必須ではありません。出力は採用音声を使い、分割境界・ファイル名・既定／ブロック別間隔・ノーマライズを適用してFLAC/WAVを生成します。プレビューは選択位置から再生し、停止操作を共通に扱います。

## 検証の範囲

UIはDOM・RPCモック、Rustは保存・境界・音声加工・出力などを試験します。外部環境を要するignored試験は明示実行が必要です。自動試験はネイティブキー、マイクの人声音質、OSダイアログの代替ではありません。[検証記録](validation.md)に実施条件と残る確認を分けて記載します。

## v0.0.3の保存・原稿管理

保存形式5は、現役のscript_sourcesに加えpending_source_deletionsとarchived_sourcesを保持する。削除予定は下書き保存し、台本確定で原稿と発話をアーカイブへ移す。全原稿削除後の空の配列は正当な状態であり、旧形式移行で原稿を再生成しない。取込元ファイルのパスは保存せず、名前と本文を保持する。

同名への名前変更は通常の同名取込と同じ差分基準を使う。行対応付けはprevious_idから継承意思を導出し、(新規)を明示した行には自動対応を再適用しない。

完全消去は全保存世代・現在状態・索引から対象の原稿情報と発話参照を除去する。専有音声とASR成果物は削除し、共有音声は保持する。pendingジャーナルで再試行し、消去完了時は再試行用本文も全世代から除く。現在使用中の原稿・発話、下書き対応中の発話は消去を拒否する。


### v0.0.3追加分の操作と保存

- 行選択のreading_orderは原稿内の読み上げ順。物理行lineと本文、source_lineは移動しない。再解析時に一致する行の順序を引き継ぐ。原稿順はscript_sourcesの配列順。
- 全文左右比較はReviewRowの承認キーを共用し、同一行を軸に物理行を整列する。1つの表で左右の高さとスクロールを同期。
- .scriptsyncの起動位置引数と起動画面ドロップは既存Storeの読込経路を使用。フォルダーの再帰取込はリンクを辿らず、同名重複を拒否し、名前・本文だけを保持する。
- プロジェクト改名は同じ親に入口と所有データを移す。Windowsでは改名中マーカーを検査し、ロックの解放・フォルダー移動・再ロックを行う。入口の新規公開とタイトル保存が失敗した場合は復旧を試み、所有データを削除しない。ASRの実行中・待機中は改名を拒否する。
- 編集の復元点はセッション内の原稿別スナップショット。取込・プロジェクト読込・確定で更新する。復元自体も下書き保存し、他の原稿には影響しない。

録音欄の編集はSegment.recording_draftへ保存し、確定本文・読み・テイクを直接変更しない。recording_feedbackが元原稿位置の照合後にsourceの下書き保存と修正原稿の消費を同時保存する。確定時は再利用Segmentのtextも更新し、対象外はarchived_segmentsへ移す。

# 現行アーキテクチャ

## この文書を読むとき

次の変更を設計・実装・レビューするときは、作業前に本書を読みます。

- `.scriptsync`、保存世代、保存形式、旧形式移行を変更するとき
- 原稿、確定台本、修正案、発話、テイクの関係を変更するとき
- 録音、トリム、再生デバイス、音声出力の責務を変更するとき
- Whisper、Codex CLI、TextToSpeech CLIとの境界を変更するとき
- ZIP交換、Web送信、結合出力、字幕やブロックマップを変更するとき
- 複数モジュールにまたがる変更の担当範囲を判断するとき

本書は現行版から今後の版へ引き継ぐ構造と不変条件を説明します。特定バージョンの実装経緯、試験件数、成果物、当時の未確認事項は対象版の `dev/vX.Y.Z-imp.md` または `dev/history/vX.Y.Z/` を参照してください。初期構想は[初期設計案](history/architecture-initial-design.md)、ファイル単位の担当は[構成目録](REPOSITORY_MAP.md)に分けています。

## 処理の境界

TypeScript UIからTauriコマンドを通してRustへ操作を渡します。UIは5工程の表示、編集中の状態、利用者操作を管理し、Rustはプロジェクト保存、録音、音声加工、端末設定、外部処理を担当します。

UIだけで保存成功を確定せず、Rustの応答と保存済みスナップショットを正本にします。非同期処理では、開始時のプロジェクト、原稿、発話、テイク、本文版を固定し、処理中に対象が変わった結果を古い状態へ適用しません。

## プロジェクト、保存世代、互換性

プロジェクトの入口は `.scriptsync` ファイル、データ本体は対応する `.scriptsync.data/` です。この2つを一組で扱います。データ内の不変な `revisions/` が保存世代の正本で、`project.json`は索引です。最新世代が破損した場合に、黙って古い世代へ戻して成功扱いにはしません。

現在の保存形式は5です。形式1～4を読み込み、録音と過去世代を保持して移行します。形式5を古いアプリで開けるとは限りません。未知の将来形式は版番号だけを書き換えて取り込まず、対応範囲を示して停止します。

保存は一時ファイルと置換を使い、失敗時は直前の正常な世代、既存音声、端末設定を保持します。プロジェクトのロック、保存待ち、保存失敗を区別し、画面を閉じるだけで未保存データを失わないようにします。

## 原稿、台本、修正案

「原稿」は取り込んだMarkdown／テキスト、「台本」は読み上げ対象を選んで確定した本文です。原稿ごとに安定したID、名前、確定本文、下書き、解析済み行を保持し、発話は原稿IDと元の行位置へ対応します。

MarkdownのH1／H2／H3は部／章／節として扱い、下位見出しが存在する階層だけを作ります。見出しより前の本文は必要な場合だけ第0グループへまとめます。読み上げ対象外の発話は録音対象から外しますが、明示的な完全消去までは録音を保持します。

台本画面の編集は下書きとして保存できても、確定本文を直接変更しません。「台本確定」で選択、順序、対応付け、削除予定を検査して確定本文と発話を更新します。再編集後は再確定するまでZIP出力とWeb送信を許可しません。

録音画面の修正案は `Segment.recording_draft` として確定台本から分離して保存します。手動編集、Whisper結果の反映、AI文章改善は同じ修正案を扱います。台本画面へ戻ったときに元原稿の対応位置へ反映し、競合する別編集があれば無断で上書きしません。

原稿・発話の削除はまずアーカイブへ移します。完全消去は明示確認後だけ行い、pendingジャーナルを保存して全世代の参照を除去します。共有参照のある音声は保持し、中断時は再試行できる状態を残します。

## 録音と音声

録音はローカルの `scriptsync-recorder` crateを使用します。WASAPI入力、連続リサンプリング、WAV書き込み、入力不連続・欠落・バッファ状態の診断を録音基盤で扱い、アプリ側がテイクとして保存します。入力欠落の補償は失われた発話内容を復元したことを意味しません。

録音開始時にWindowsの既定入力、または利用者が指定した入力endpointを解決します。開始・収録に失敗した仮テイクは一覧へ残しません。正常に取得した音声の最終保存だけが失敗した場合は、復旧用音声と診断を保持します。

保存時の自動端部処理と、利用者が確定する手動トリムを分けます。トリム保存では音声実体、参照hash、長さを一緒に更新します。波形と再生位置は保存後の音声時間を基準にします。

テイク、トリム、比較、アーカイブ、完成音声、効果音は端末設定で選んだ再生先を使います。端末設定はプロジェクトへ保存せず、このPCのアプリ設定として管理します。明示指定した機器が消失したときに別機器へ黙って切り替えません。

## 操作状態と録音の寿命

通常録音は画面内の操作、連続録音は明示開始から終了までのグローバルキーを使用します。保存済みテイクと収録中の一時データを分け、取り消し操作で過去の保存済み音声を消しません。キー仕様の正本は[キー定義](../dev/SHORTCUT_KEYS.md)です。

UIの誤リロードを防止し、Rust側でUIセッションの生存を監視します。UI再接続や喪失が起きても、収録が操作不能のまま継続しないよう停止・復旧経路を持ちます。

## 文字起こしとAI文章改善

Whisperはアプリ専用のローカルPython環境で音声を文字起こしします。環境とモデルは端末単位で管理し、プロジェクトへ含めません。認識結果は候補として元テイクに保持し、確定台本を直接変更しません。

Codex CLIによる文章改善はWhisperとは独立した任意操作です。音声は送らず、確定台本と修正案を校正用入力として渡します。端末設定の静的変換辞書を一度だけ前処理し、AI結果は改善前後を比較して利用者が承認した場合だけ修正案へ反映します。処理中に入力や選択対象が変わった結果は適用しません。

認識・AI結果・読み補正はすべて候補です。人間の確認なしに正解や確定本文へ昇格させません。TextToSpeech CLIはテキストを音声へ変換する外部CLIの抽象名であり、具体的な交換形式は[形式資料](talk-project-format.md)を参照してください。

## 交換と出力

録音の採用だけで結合出力へ進めます。読み確認と比較採点は任意です。出力は確定済み台本の有効な発話と採用音声を使い、分割境界、ファイル名、前後・階層間隔、ノーマライズを適用してFLAC／WAVを生成します。

字幕と `block-map.json` は音声と同じ時間軸から生成します。音声、VTT、ブロックマップで別々に時刻を再計算しません。公開する形式契約は[音声・字幕・ブロックマップ連携仕様](EXPORT_BLOCK_MAP.md)に置きます。

Web交換ZIPは確定台本と明示された音声だけを扱い、既存録音を推測で対応させません。Web送信は暗号化ZIPを専用APIへ送り、HNとキーを端末設定やプロジェクトへ保存しません。OneDriveやBoxへの直接認証・直接送信は行わず、必要な場合は利用者が出力ZIPをアプリ外で管理します。

## 検証の境界

UI試験はDOMとRPC契約、Rust試験は保存、境界、音声加工、出力、移行を確認します。ブラウザーのRPCモック、自動試験、EXE起動だけでは、実マイク音質、指定機器からの聴感、ネイティブダイアログ、非アクティブ時キーを確認済みにしません。

変更に必要な検証の選び方は[実証・受け入れ方針](validation.md)と[プロジェクト専用の変更検証スキル](../.agents/skills/scriptsync-project-validation/SKILL.md)を参照し、実行結果は対象版のIMPへ記録します。
